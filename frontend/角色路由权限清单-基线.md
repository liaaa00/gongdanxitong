# 前端角色路由权限清单（当前基线）

> 数据来源：frontend/src/config/routeVisibility.ts
> 提取时间：2026-08-01
> 说明：本清单基于 ROUTE_VISIBILITY 配置整理，反映前端当前路由权限配置基线

---

## 一、角色定义（共9个规范角色）

| 角色代码 | 角色名称 | 说明 |
|---------|---------|------|
| `admin` | 系统管理员 | 全部权限 |
| `business_owner` | 业务负责人 | 查看全部业务工单，不可操作 |
| `business_group_leader` | 业务组长 | 查看本组工单，可发起/修改/撤回 |
| `business_group_member` | 业务员 | 只看自己发起的工单 |
| `data_entry_leader` | 数据录入组长 | 增减员报岗录入模块全量 |
| `shared_team_owner` | 共享团队负责人 | 合同+入离职联系模块 |
| `labor_contract_member` | 合同专员 | 劳动合同新签/续签 |
| `onboarding_resignation_member` | 入离职专员 | 入职联系/离职材料收集 |
| `social_insurance_specialist` | 福保负责人 | 社保公积金增减员 |

## 四、权限判断逻辑说明

### 4.1 双重权限系统
前端存在两套权限判断机制：

1. **静态角色权限（ROUTE_VISIBILITY）**
   - 基于角色直接配置路由可访问性
   - 优先级：先检查角色是否在允许列表中

2. **动态权限码（ROUTE_ACTION_PERMISSIONS）**
   - 基于权限码动态判断
   - 优先级：角色不匹配时检查权限码

### 4.2 判断流程
```
用户访问路由 /onboarding/contract
  ↓
检查 ROUTE_VISIBILITY['/onboarding/contract']
  = [admin, business_group_leader, business_group_member, labor_contract_member, shared_team_owner]
  ↓
用户角色是否在列表中？
  ├─ 是 → 允许访问
  └─ 否 → 检查 ROUTE_ACTION_PERMISSIONS['/onboarding/contract']
            = ['route.onboarding_contract', 'module.contract.manage']
            ↓
            用户是否拥有任一权限码？
              ├─ 是 → 允许访问
              └─ 否 → 拒绝访问（重定向 /403）
```

## 五、核心发现与问题

### 5.1 发现
1. **admin 拥有全部72个路由访问权限**
2. **业务侧角色（business_*）主要操作主工单和省外业务**
3. **后道角色（data_entry/shared_team/labor_contract等）主要操作子工单和专业模块**
4. **"我的工单"6个视图仅 admin 可访问**（initiated/returned/pending/done/team/history）
5. **所有角色都可访问在职管理（IN_SERVICE_ROLES）**

### 5.2 问题
1. **业务组长和业务员无法访问 `/onboarding` 入口**，但可访问其下所有子工单路由
2. **business_owner 只有27个路由权限**，无法访问主工单列表，不符合"查看全部业务工单"的角色定义
3. **部分路由配置为空数组**（如 `/onboarding/resignation_cert`, `/offboarding/proof-pool`），任何角色都无法访问
