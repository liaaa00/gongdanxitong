# 生产部署手册

> 适用范围：当前 Docker Compose 生产部署。本文只准备配置和脚本，不代表已经改动任何生产环境或生产数据。

## 1. 前置条件

- Linux 或 Windows Server、Docker Engine 26+、Docker Compose 2.24+、Windows PowerShell 5.1 或 PowerShell 7+。
- DNS 已将业务域名指向服务器。
- 已取得 PEM 格式证书和私钥，证书文件对 Docker 可读，私钥仅管理员可读。
- 服务器至少预留 4 GB 内存和独立的数据、备份磁盘。

生产拓扑为：`HTTPS -> Nginx -> frontend/backend -> PostgreSQL`。PostgreSQL、Prometheus、Grafana 默认只绑定 `127.0.0.1`；Grafana 通过 `https://<域名>/grafana/` 访问，后端指标端点不对公网开放。

## 2. 生成生产配置

不要从 `.env.example` 直接启动生产。运行生成器创建被 Git 忽略的 `.env.production.local`：

```powershell
pwsh ./deploy/Generate-ProductionEnv.ps1 `
  -PublicHostname work-order.example.com `
  -TlsCertFile /etc/letsencrypt/live/work-order.example.com/fullchain.pem `
  -TlsKeyFile /etc/letsencrypt/live/work-order.example.com/privkey.pem
```

脚本分别生成 64 字节 JWT 密钥、刷新密钥、数据库密码和 Grafana 密码，且不会把密钥打印到终端。生成后按需填写 `AI_API_KEY`，并将环境文件交由主机密钥管理或配置管理系统保管。

生产覆盖层会拒绝缺少以下变量的启动：

- `POSTGRES_DB`、`POSTGRES_USER`、`POSTGRES_PASSWORD`
- `JWT_SECRET`、`JWT_REFRESH_SECRET`
- `TLS_CERT_FILE`、`TLS_KEY_FILE`
- `PUBLIC_HOSTNAME`、`GRAFANA_ROOT_URL`、`GRAFANA_ADMIN_PASSWORD`

## 3. 上线前校验

```powershell
docker compose --project-name ticket-system --env-file .env.production.local `
  -f docker-compose.yml `
  -f docker-compose.production.yml config --quiet

docker run --rm `
  -v "${PWD}/nginx/nginx.production.conf:/etc/nginx/nginx.conf:ro" `
  -v "/etc/letsencrypt/live/work-order.example.com/fullchain.pem:/etc/nginx/tls/fullchain.pem:ro" `
  -v "/etc/letsencrypt/live/work-order.example.com/privkey.pem:/etc/nginx/tls/privkey.pem:ro" `
  nginx:1.27-alpine nginx -t
```

安全检查：

- 防火墙只对公网开放 80/443；5432、9090、3001 不得公网可达。
- `.env.production.local` 权限为 `600`，且未被 Git 跟踪。
- 证书域名正确、证书链完整、有效期不少于 30 天。
- `AUTO_SEED=false`；生产 seed 仅在明确评审后通过 `-RunSeed` 执行。
- `/api/metrics` 从业务域名访问返回 404。

## 4. 迁移和部署

迁移脚本会依次校验 Compose、等待 PostgreSQL 健康、执行 `pg_dump` 自定义格式备份、运行 TypeORM migration，最后启动应用和监控服务：

```powershell
pwsh ./deploy/Invoke-ProductionMigration.ps1
```

备份写入 Git 忽略的 `backups/ticket-system-<timestamp>.dump`。首次部署确实需要初始化配置数据时，经评审后显式执行：

```powershell
pwsh ./deploy/Invoke-ProductionMigration.ps1 -RunSeed
```

迁移前不得删除旧容器卷或手工修改 `migrations` 表。迁移失败时保持流量在旧版本，先保存日志并使用对应备份在隔离数据库演练恢复；未经验证不要直接执行 migration revert。

## 5. 验收

```powershell
docker compose --project-name ticket-system --env-file .env.production.local `
  -f docker-compose.yml `
  -f docker-compose.production.yml ps

Invoke-WebRequest https://work-order.example.com/healthz -UseBasicParsing
Invoke-WebRequest https://work-order.example.com/api/health -UseBasicParsing
Invoke-WebRequest http://127.0.0.1:9090/-/healthy -UseBasicParsing
Invoke-WebRequest https://work-order.example.com/grafana/api/health -UseBasicParsing
```

同时验证登录、首次改密、创建工单、附件上传下载、SSE 通知和数据库迁移版本。Prometheus 告警规则至少覆盖后端不可用、5xx 比例超过 5% 和 P95 延迟超过 2 秒。

## 6. 日常运维

- 每日数据库备份，保留 30 天；至少每月做一次隔离恢复演练。
- 证书到期前 30 天告警，续期后执行 `docker compose ... restart nginx`。
- 每次升级都先运行迁移脚本生成备份，再切换应用。
- 每季度轮换 JWT、数据库和 Grafana 凭证。轮换 JWT 会使现有会话失效，应安排维护窗口。
- Prometheus 默认保留 30 天；Grafana 管理员密码不得与系统账号复用。
