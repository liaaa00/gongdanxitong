## 4. 本轮发现并修复的问题

### 4.1 P3-E2E-002：dispatched-orders 四模块列表 500

- 问题：TypeORM join + pagination 场景中使用数据库列名 `.orderBy('d.created_at')` 会触发 `Cannot read properties of undefined (reading 'databaseName')`，最终被统一过滤器包装成 HTTP 500 / `code=1000`。
- 修复：改为实体属性路径 `.orderBy('d.createdAt', 'DESC')`。
- 文件：`backend/src/modules/dispatched-orders/dispatched-order.service.ts:70`。
- 验证：`data_entry`、`social_security`、`onboarding_contact`、`contract` 四模块列表最终 smoke 均 HTTP 200。

### 4.2 FINAL-FILE-DOWNLOAD-001：导出文件已落盘但 `/api/files/:id` 下载 500

- 问题 1：下载控制器使用 `@Res({ passthrough: true })` 且 `return stream.pipe(res)`，可能导致响应拦截器尝试包装流/Response 对象。
- 问题 2：导出文件由 `UploadService.saveBuffer` 写入 `uploads/excel/<fileId>.xlsx`，进程重启或跨模块实例时仅靠内存索引不可靠，需要从磁盘恢复定位。
- 修复：
  - 下载接口改为 `@Res()` 并直接 `stream.pipe(res)`，不再返回流对象。
  - `UploadService.findFileByPrefix` 增强为先检查 `<fileId>.xlsx` 等直接候选路径，再递归兜底。
- 文件：
  - `backend/src/modules/upload/file.controller.ts:10`
  - `backend/src/modules/uploads/uploads.controller.ts:59`
  - `backend/src/modules/upload/upload.controller.ts:45`
  - `backend/src/modules/upload/upload.service.ts:96-132`
- 验证：`POST /api/export-templates/:id/apply` 返回 fileId 后，`GET /api/files/:fileId` HTTP 200，MIME 为 Excel。

### 4.3 导出模板 loadOrders 潜在同类 TypeORM 排序问题

- 问题：`ExportTemplatesService.loadOrders` 仍使用 `d.module_code` / `d.created_at` 数据库列名。
- 修复：改为 `d.moduleCode` / `d.createdAt`。
- 文件：`backend/src/modules/admin/export-templates/export-templates.service.ts:162-163`。
