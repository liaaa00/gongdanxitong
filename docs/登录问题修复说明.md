# 登录问题修复说明

## 问题描述
只有管理员账号（admin）可以登录，其他账号（包括种子用户和新创建的用户）都无法登录。

## 根本原因
`ensureSeedPasswords()` 函数的逻辑缺陷：当 localStorage 中已经存在任何密码条目时（比如只有 admin 的密码），该函数会直接返回，不会为其他种子用户创建密码。

这导致在以下场景下出现问题：
1. 用户删除了部分数据
2. 系统重新初始化用户列表（9个种子用户）
3. 但只有部分用户有密码（通常只有 admin）
4. 其他用户无法登录

## 修复内容

### 1. 修复 `ensureSeedPasswords()` 函数
**文件**: `frontend/src/services/users.ts`

**修改前**:
```typescript
function ensureSeedPasswords() {
  const existing = loadPasswords();
  if (existing.length > 0) return;  // ⚠️ 问题：只要有任何密码就返回
  const entries: PasswordEntry[] = Object.entries(DEFAULT_SEED_PASSWORDS).map(([username, password_hash]) => ({
    username,
    password_hash,
  }));
  savePasswords(entries);
}
```

**修改后**:
```typescript
function ensureSeedPasswords() {
  const existing = loadPasswords();
  const existingUsernames = new Set(existing.map(p => p.username));

  // 检查是否有种子用户缺少密码
  const missingPasswords: PasswordEntry[] = [];
  for (const [username, password_hash] of Object.entries(DEFAULT_SEED_PASSWORDS)) {
    if (!existingUsernames.has(username)) {
      missingPasswords.push({ username, password_hash });
    }
  }

  // 如果有缺失的密码，添加它们
  if (missingPasswords.length > 0) {
    const updated = [...existing, ...missingPasswords];
    savePasswords(updated);
  }
}
```

### 2. 添加诊断工具
**文件**: `frontend/src/utils/diagnoseAuth.ts`

提供了两个浏览器控制台命令：
- `diagnoseAuth()`: 诊断认证问题，显示用户和密码的匹配情况
- `fixAuth()`: 自动修复认证问题，为缺少密码的用户创建默认密码

### 3. 添加单元测试
**文件**: `frontend/src/services/users.test.ts`

测试覆盖：
- 种子用户密码验证
- 新用户创建和登录
- 错误密码拒绝
- 不存在用户拒绝
- 所有种子用户密码完整性

## 使用方法

### 方法一：自动修复（推荐）
1. 打开浏览器开发者工具（F12）
2. 切换到 Console（控制台）标签
3. 输入以下命令并回车：
   ```javascript
   diagnoseAuth()  // 先诊断问题
   fixAuth()       // 自动修复
   ```
4. 刷新页面
5. 现在所有用户都可以登录了

### 方法二：清空数据重新开始
1. 打开浏览器开发者工具（F12）
2. 切换到 Application（应用）标签
3. 左侧选择 Local Storage
4. 删除以下键：
   - `mock_admin_users_v1`
   - `mock_admin_passwords_v1`
   - `mock_session_user_v1`
5. 刷新页面
6. 系统会自动重新初始化所有数据

### 方法三：手动清空所有 Mock 数据
在浏览器控制台执行：
```javascript
localStorage.clear()
location.reload()
```

## 预防措施

为了避免将来再次出现此问题：

1. **不要手动删除 localStorage 中的单个键**，如果需要重置数据，请清空所有 Mock 相关的键
2. **创建新用户时务必设置密码**（表单已强制要求）
3. **定期运行 `diagnoseAuth()` 检查数据一致性**

## 技术细节

### 密码存储机制
- 密码存储在 `localStorage` 的 `mock_admin_passwords_v1` 键中
- 格式：`[{ username: string, password_hash: string }]`
- 注意：当前是明文存储（Mock 模式），生产环境应使用真实的哈希算法

### 用户-密码同步
- 用户数据存储在 `mock_admin_users_v1`
- 密码数据存储在 `mock_admin_passwords_v1`
- 两者通过 `username` 关联
- `ensureSeedPasswords()` 确保所有种子用户都有密码
- `setUserPassword()` 在创建/更新用户时同步密码

### 登录验证流程
1. `auth.ts::login()` 调用 `validateUserCredentials()`
2. `validateUserCredentials()` 查找用户并验证密码
3. 如果验证成功，返回用户信息并创建会话
4. 会话存储在 `mock_session_user_v1`
