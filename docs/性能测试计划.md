# 性能测试计划

## 1. 目标

本计划用于 Phase 3 之后建立入职工单系统的性能基线，覆盖批量导入、文件上传、列表查询、批量更新和报表导出等高频/高成本路径。

## 2. 测试阶段

| 阶段 | 触发条件 | 测试重点 |
|---|---|---|
| Phase 3 后 | 工单创建、提交、派发链路完成 | 列表查询、提交派发、权限过滤 |
| Phase 4 后 | Excel 导入、AI 映射、字段补充完成 | 1000 行导入、错误报表、附件上传 |
| Phase 5 后 | 撤回审批、导出模板完成 | 一键导出、批量状态更新、审批并发 |
| Phase 6 前 | 看板和通知完成 | Dashboard 聚合查询、端到端容量回归 |

## 3. 工具选型

| 工具 | 用途 | 原因 |
|---|---|---|
| k6 | API 压测、场景编排、阈值断言 | 脚本化强，适合 CI 基线 |
| autocannon | Node API 快速吞吐测试 | 轻量，适合本地快速回归 |
| PostgreSQL EXPLAIN ANALYZE | 慢查询定位 | 验证索引、JSONB/GIN 查询效果 |
| Docker stats | 容器资源观察 | 本地部署形态一致 |

## 4. 环境要求

- 使用 Docker Compose 部署 postgres/backend/frontend/nginx。
- 测试库与开发库隔离，性能测试前重置数据。
- 固定硬件规格并记录 CPU、内存、磁盘、Node 版本、PostgreSQL 版本。
- 关闭调试日志，保留请求 traceId 和错误日志。

## 5. 基线指标

| 场景 | 数据规模 | 目标指标 |
|---|---:|---|
| 登录接口 | 50 VU，持续 1 分钟 | p95 < 300ms，错误率 < 0.1% |
| 工单列表分页 | 10 万主工单，pageSize=20 | p95 < 500ms |
| 子工单列表分页 | 30 万子工单，按模块过滤 | p95 < 600ms |
| 创建并提交工单 | 单条，触发 2~4 子工单 | p95 < 800ms，无重复子工单 |
| Excel 导入 | 1000 行，54 字段 | 总耗时 < 60s，错误行报告可下载 |
| 附件上传 | 10MB 文件，20 并发 | p95 < 3s，失败率 < 1% |
| 一键导出 | 1000 条子工单，30 字段 | 总耗时 < 30s |
| 批量更新状态 | 1000 条子工单 | 总耗时 < 20s，事务一致 |
| 看板聚合 | 当月 10 万记录 | p95 < 1s |

## 6. 核心用例样本

### PERF-001 导入 1000 行 Excel

- 前置：准备 1000 行入职 Excel，包含合法行、缺必填、下拉非法、身份证格式错误样本。
- 步骤：
  1. 上传 Excel。
  2. 确认字段映射。
  3. 提交导入。
  4. 轮询 import job 状态。
- 采集：总耗时、成功行、失败行、CPU、内存、数据库写入耗时。
- 阈值：总耗时 < 60s；失败行报告生成成功；系统无 5xx。

### PERF-002 列表查询分页

- 前置：生成 10 万主工单、30 万子工单。
- 步骤：使用 k6 对 `/api/work-orders?page=1&pageSize=20`、`/api/dispatched-orders?moduleCode=contract` 发起 50 VU 查询。
- 采集：p50/p90/p95/p99、错误率、数据库慢查询。
- 阈值：主工单 p95 < 500ms；子工单 p95 < 600ms。

### PERF-003 批量更新状态

- 前置：准备 1000 条 pending 子工单。
- 步骤：调用批量完成或批量状态更新接口。
- 采集：总耗时、事务成功率、父工单状态一致性。
- 阈值：总耗时 < 20s；任何失败应整体回滚或明确返回部分失败策略。

### PERF-004 报表一键导出

- 前置：存在导出模板和 1000 条可导出子工单。
- 步骤：调用导出接口，下载文件。
- 采集：导出耗时、文件大小、内存峰值、字段正确性。
- 阈值：总耗时 < 30s；导出字段不得包含 hidden 字段。

### PERF-005 附件上传

- 前置：准备 1MB、10MB、50MB 三类文件。
- 步骤：20 并发上传附件。
- 采集：p95、失败率、磁盘占用、文件校验。
- 阈值：10MB 文件 p95 < 3s；50MB 文件不超出配置限制时应成功，超出时返回明确错误。

## 7. k6 脚本草案

```js
import http from 'k6/http';
import { check, sleep } from 'k6';

export const options = {
  vus: 50,
  duration: '1m',
  thresholds: {
    http_req_failed: ['rate<0.001'],
    http_req_duration: ['p(95)<500'],
  },
};

const BASE_URL = __ENV.BASE_URL || 'http://localhost:8080';
let token = __ENV.ACCESS_TOKEN;

export default function () {
  const res = http.get(`${BASE_URL}/api/work-orders?page=1&pageSize=20`, {
    headers: { Authorization: `Bearer ${token}` },
  });
  check(res, {
    'status is 200': (r) => r.status === 200,
    'has traceId': (r) => Boolean(r.json('traceId')),
  });
  sleep(1);
}
```

## 10. 风险关注

- JSONB 字段查询若缺少索引，列表和看板可能退化为全表扫描。
- 字段权限过滤若在应用层对大结果集逐条处理，可能导致接口 p95 升高。
- Excel 导入应异步 job 化，避免 HTTP 请求超时。
- 导出大文件应流式生成，避免内存峰值过高。
- 批量更新必须明确事务策略和失败返回格式。
