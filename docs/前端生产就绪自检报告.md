## §4 Nginx 配置核验（`nginx/nginx.conf`）

核验四项必检：

| # | 检查项 | 位置 | 配置摘要 | 结论 |
|---|---|---|---|---|
| 1 | `/api` 反向代理到 backend | L85-98 | `location /api/ { proxy_pass http://ticket_backend; ... proxy_read_timeout 300s; proxy_buffering on; }` | ✅ 常规 API 走 buffering + 300s 超时 |
| 1-附 | SSE（`/api/events/...`、`/api/notifications/...`）单独处理 | L71-83 | `location ~ ^/api/(events\|notifications)/ { proxy_buffering off; proxy_cache off; chunked_transfer_encoding on; proxy_read_timeout 1h; Connection ""; }` | ✅ 关闭缓冲 + 1h 长读超时，匹配 Phase 6 SSE 心跳实际场景 |
| 2 | SPA fallback | L117-124 | `location / { proxy_pass http://ticket_frontend; ... }` 转到 frontend 容器内 nginx；frontend 容器内 `frontend/nginx.conf` L8-10 `try_files $uri $uri/ /index.html;` | ✅ SPA fallback 由前端容器内 nginx 兜底，两层结构正确 |
| 3 | 静态缓存头 | frontend 容器内 `nginx.conf` 默认 + 上层 gzip | `gzip on; gzip_types text/plain text/css application/javascript ...;` 顶层 gzip 开启；frontend 容器目前未显式加 `Cache-Control: immutable`（Vite 已用内容哈希命名，浏览器自行用协商缓存不成问题） | ⚠️ **非阻塞建议**：生产环境可在 frontend 容器内 nginx 的 `/assets/` location 显式加 `expires 30d; add_header Cache-Control "public, immutable";`，提升二次加载命中率 |
| 4 | `/files` X-Accel-Redirect | L108-113 | `location /files/ { alias /var/www/uploads/; internal; add_header Cache-Control "private, no-cache"; }` | ✅ 后端通过 `X-Accel-Redirect: /files/xxx` 触发 nginx 直传文件，`internal` 防止外部直访，`private, no-cache` 保证敏感附件不被 CDN/浏览器缓存 |

### 附加收益核验
- L64-67 四个安全响应头（X-Frame-Options / X-Content-Type-Options / X-XSS-Protection / Referrer-Policy）全部 `always` ✅
- L30 `client_max_body_size 50m` 与后端 `MAX_UPLOAD_SIZE_MB=20` 匹配（nginx 限 50M > 业务限 20M / 导入限 10M，留足裕度）✅
- L49-57 两个 upstream 分别 `keepalive 32` / `16`，压测友好 ✅

**结论**：Nginx 四项必检全过，1 条非阻塞优化建议（静态资源 immutable 缓存头）可在生产环境收敛。

- 仓库的前端配置仍然符合生产部署要求 ✅
- 技术栈描述与实际代码一致 ✅
- MSW / SSE / SPA fallback / 附件代下载链路配置正确 ✅
