# 用户管理页面重复性检查功能

## 功能概述

在用户管理页面添加新用户或编辑用户时，系统会自动检查用户名和姓名是否已被其他用户使用，防止重复数据。

## 实现方案

### 1. 校验时机
- **提交时校验**：在用户点击"确定"按钮提交表单时进行校验
- 不采用实时校验，避免频繁请求影响性能

### 2. 校验规则

#### 新建用户时
- 检查用户名是否与现有用户重复
- 检查姓名是否与现有用户重复
- 如果同时重复，提示"用户名和姓名均已存在"

#### 编辑用户时
- 检查用户名是否与**其他用户**重复（排除当前用户自身）
- 检查姓名是否与**其他用户**重复（排除当前用户自身）
- 允许用户保持原有的用户名和姓名不变

### 3. 错误提示

系统会根据不同情况显示友好的错误提示：

| 情况 | 错误提示 |
|------|---------|
| 仅用户名重复 | "用户名已存在，请使用其他用户名" |
| 仅姓名重复 | "姓名已被使用，请使用其他姓名" |
| 用户名和姓名都重复 | "用户名和姓名均已存在" |

### 4. 技术实现

#### Mock 模式
- 在 `createUser` 函数中添加重复性检查逻辑
- 在 `updateUser` 函数中添加重复性检查逻辑（排除当前用户）
- 检查失败时返回 Promise.reject 并携带具体错误信息

#### 真接口模式
- 后端在创建/更新用户接口中进行校验
- 返回 400 错误并携带具体错误信息
- 前端捕获错误并显示给用户

## 代码修改说明

### 修改文件 1：`frontend/src/services/users.ts`

#### createUser 函数
添加了重复性检查逻辑：
```typescript
// 检查用户名和姓名是否重复
const duplicateUsername = list.find(u => u.username === data.username);
const duplicateRealName = list.find(u => u.real_name === data.real_name);

if (duplicateUsername && duplicateRealName) {
  return mockDelay(Promise.reject(new Error('用户名和姓名均已存在')));
}
if (duplicateUsername) {
  return mockDelay(Promise.reject(new Error('用户名已存在，请使用其他用户名')));
}
if (duplicateRealName) {
  return mockDelay(Promise.reject(new Error('姓名已被使用，请使用其他姓名')));
}
```

#### updateUser 函数
添加了重复性检查逻辑（排除当前用户）：
```typescript
// 检查用户名和姓名是否与其他用户重复（排除当前用户自身）
const duplicateUsername = list.find(u => u.id !== id && u.username === data.username);
const duplicateRealName = list.find(u => u.id !== id && u.real_name === data.real_name);

if (duplicateUsername && duplicateRealName) {
  return mockDelay(Promise.reject(new Error('用户名和姓名均已存在')));
}
if (duplicateUsername) {
  return mockDelay(Promise.reject(new Error('用户名已存在，请使用其他用户名')));
}
if (duplicateRealName) {
  return mockDelay(Promise.reject(new Error('姓名已被使用，请使用其他姓名')));
}
```

## 后续优化建议

### 1. 后端实现
当前仅在 Mock 模式下实现了重复性检查。后端需要：
- 在 `POST /api/admin/users` 接口中添加重复性校验
- 在 `PUT /api/admin/users/:id` 接口中添加重复性校验
- 返回 400 状态码和具体的错误信息

### 2. 实时校验（可选）
如果需要更好的用户体验，可以考虑：
- 在用户名输入框添加 `onBlur` 事件，失焦时检查重复
- 在姓名输入框添加 `onBlur` 事件，失焦时检查重复
- 使用防抖（debounce）避免频繁请求

### 3. 数据库约束
建议在数据库层面添加唯一约束：
```sql
ALTER TABLE users ADD CONSTRAINT uk_username UNIQUE (username);
ALTER TABLE users ADD CONSTRAINT uk_real_name UNIQUE (real_name);
```

## 注意事项

1. **Mock 模式限制**：当前实现仅在 Mock 模式下生效，真实后端接口需要单独实现
2. **大小写敏感**：当前检查是大小写敏感的（"Admin" 和 "admin" 被视为不同）
3. **空格处理**：当前未对用户名和姓名进行 trim 处理，前后空格会被视为不同
4. **性能考虑**：Mock 模式下使用数组遍历查找，数据量大时可能影响性能
