## 【进行中 / 待解决的 Bug】⚠️

> 记录格式：每项必须包含“发现日期 / 影响范围 / 优先级 / 当前状态 / 下一步验证方式”。

### BUG-001：多 worktree 与分支来源混杂
- **发现日期**：2026-05-29
- **影响范围**：仓库集成、评审、后续任务认领。
- **优先级**：P1
- **当前状态**：存在多个历史 worktree 和分支，容易让评审使用的 integration worktree 与主工作区内容不一致。
- **下一步验证方式**：只读执行 `git worktree list` 与 `git branch --all`，输出“保留 / 待合并 / 待删除 / 不处理”清单；未经 Leader 确认前不直接删除。

### BUG-002：主工作区仍有大量未收敛改动与测试产物
- **发现日期**：2026-05-29
- **影响范围**：代码评审、回归判断、文档准确性。
- **优先级**：P1
- **当前状态**：`git status` 显示大量 modified / untracked 文件，包含源码、测试、上传文件、coverage、截图、backup JSON 等混合产物。
- **下一步验证方式**：按路径分类输出清单，先区分源码改动、文档改动、测试证据、运行产物，再由 Leader 决定保留或清理。

### BUG-003：密码哈希库存在双实现风险
- **发现日期**：2026-05-29
- **影响范围**：认证、密码重置、Docker 构建兼容性。
- **优先级**：P2
- **当前状态**：依赖中可见 `bcrypt` 与 `bcryptjs` 双实现，后续维护时可能出现不同代码路径。
- **下一步验证方式**：全仓搜索 `bcrypt` / `bcryptjs` import 与 require，确认真实使用点，再通过小步任务统一实现。

### BUG-004：依赖版本口径需要与 TECH_STACK 保持一致
- **发现日期**：2026-05-29
- **影响范围**：安装复现、构建、AI 查文档时的版本判断。
- **优先级**：P2
- **当前状态**：项目依赖声明、lockfile、TECH_STACK 文档之间需要持续核对，避免再次出现“声明版本 / 实装版本 / 文档版本”三套口径。
- **下一步验证方式**：只读比较 `backend/package.json`、`frontend/package.json`、对应 lockfile 与 `docs/project-rules/TECH_STACK.md`，列出不一致项，不在本任务内改依赖。

### BUG-005：旧角色码与 canonical 角色码仍有兼容包袱
- **发现日期**：2026-05-29
- **影响范围**：权限判断、路由可见性、重新 seed 后的数据一致性。
- **优先级**：P2
- **当前状态**：系统中存在后端旧角色码到前端规范角色码的兼容映射。
- **下一步验证方式**：用测试覆盖角色归一化输入输出，并复核 seed 幂等逻辑，不直接删除旧码兼容层。

### BUG-006：历史迁移中存在反复启停字段
- **发现日期**：2026-05-29
- **影响范围**：数据库迁移、字段配置、催办相关业务。
- **优先级**：P2
- **当前状态**：社交催办相关字段历史上出现 disable / restore 循环，说明该能力边界较脆弱。
- **下一步验证方式**：复核迁移顺序与当前 Entity 字段是否一致，补一条迁移顺序回归或 schema guard 断言。

### BUG-007：Pool 策略子工单并发认领仍需加固
- **发现日期**：2026-05-29
- **影响范围**：子工单分配、公平性、数据一致性。
- **优先级**：P1

- **下一步验证方式**：编写“两个处理人同时认领同一条 pool 子工单”的集成测试，断言只允许一个成功。

### BUG-008：AI 字段映射降级路径仍需验证

### BUG-009：大文件导入与事务超时边界未充分压测

- **下一步验证方式**：准备 5000 行样例，分别验证全成功、部分失败、字段非法、重复身份证等场景。

### BUG-010：SLA 提醒定时任务需要幂等保护验证
