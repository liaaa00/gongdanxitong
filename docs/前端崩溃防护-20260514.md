## 2. ErrorBoundary 组件

**位置**: `src/components/ErrorBoundary/index.tsx`

### 功能
- **友好错误页**：崩溃后展示 antd `<Result>` + **重试** / **返回首页** 按钮，绝不白屏
- **错误详情折叠面板**：显示 `error.message` + `error.stack`，开发模式下额外显示组件堆栈
- **连续崩溃防护**：同一模块连续崩溃超过 3 次，停止渲染 fallback，展示"请刷新页面"提示，避免浏览器卡死
- **设备信息记录**：每次崩溃自动打印 `userAgent / platform / screenSize / URL / timestamp` 到 console
- **上报接口预留**：`reportErrorToServer()` 函数已就绪，后续接入后端的错误收集接口即可（目前在 `console.groupCollapsed` 内集中输出）

### 手动复测
在任意页面组件的 `render` 中临时加入：
```tsx
throw new Error('手动测试崩溃');
```
预期：该页面展示 ErrorBoundary 的友好结果页，其他页面正常。

## 3. 全局错误拦截 (`main.tsx`)

### `window.onerror`
- 捕获所有未处理的同步错误（throw / TypeError 等）
- 将错误消息 + 位置 + 堆栈输出到 `console.groupCollapsed`
- 弹出 antd `message.error('系统出现意外错误，请刷新页面后重试')`
- 设置 `return false` 阻止浏览器默认报错弹窗

### `window.onunhandledrejection`
- 捕获所有未 catch 的 Promise 异常
- 输出 `event.reason` 和堆栈
- 弹出 Toast 提示
- 调用 `event.preventDefault()` 阻止浏览器控制台标红

### 资源加载错误
- 对 `<img>`、`<script>`、`<link>` 等标签的加载失败打印警告日志

## 4. API 层防护 (`services/request.ts`)

### 增强内容
| 错误类型 | 提示文案 |
|---------|---------|
| 超时 (ECONNABORTED) | "请求超时，请检查网络后重试" |
| 5xx | "服务器异常 (500)，请稍后重试" |
| 404 | "请求的资源不存在" |
| 403 | "没有权限执行此操作" |
| 4xx（其他） | 后端 message 或 "请求失败 (4xx)" |
| 网络断开 | "网络连接失败，请检查网络" |

### 关键改进
- **超时统一上限 30s**（已导出 `TIMEOUT_MS` 常量）
- **响应拦截器统一 Toast**：`onResponseFulfilled` 和 `onResponseRejected` 中均调用 `showErrorToast()`，即使页面调用方忘记 `.catch()` 也不会静默失败
- **友好消息注入**：在 rejected error 上附加 `_friendlyMsg` 字段，调用方可直接读取

## 5. 表单/组件高风险位点修复

### 5.1 `WorkOrders/New/index.tsx` — useEffect 依赖
- **修复前**：`useEffect(..., [])` 内部使用 `computeSplit` 和 `message`，StrictMode 下可能引发竞态
- **修复后**：`computeSplit` 改为 `useCallback`，依赖数组 `[computeSplit, message]`

### 5.2 `DynamicForm/index.tsx` — 重复提交防护
- `ProForm` 的 `submitter.submitButtonProps` 已绑定 `loading` prop
- 外层调用方（WorkOrdersNew）通过 `<Button loading={submitting}>` 双重防护
- **无需额外修改**，现有机制已覆盖

### 5.3 Table rowKey
- `ProTablePage`：默认 `rowKey='id'`
- `MultiViewTable`：默认 `rowKey='id'`
- `OnboardingModule`：`rowKey="id"`
- admin 各页面：`rowKey="id"`
- rowKey 均为字符串字面量，不会出现 `undefined`

### 5.4 DatePicker / Select 错误 value 类型
- `DynamicForm` 中 `DatePicker` 使用 `ProFormDatePicker`，由 ProForm 统一管理 value 转换
- `convertDates()` 方法对 Dayjs → string 做了安全的 `'format' in value` 检查
