## 0. 最终确认结论

### 0.1 入职一拆四生成规则

| 子单 | 内部 code | 前端中文展示 | 生成规则 | 前端预览口径 |
|---|---|---|---|---|
| 数据录入 | `data_entry` | 数据录入 | 所有已提交入职工单固定生成 | 始终显示“将生成” |
| 入职联系 | `onboarding_contact` | 入职联系 | 按原有条件生成 | 展示条件命中结果和中文原因 |
| 劳动合同签订 | `contract` | 劳动合同签订 | 按原有条件生成 | 展示条件命中结果和中文原因 |
| 社保公积金办理 | `social_insurance` | 社保公积金办理 | 所有已提交入职工单固定生成 | 始终显示“将生成” |

关键变化：

1. 入职发起页不能简单写死“四个都生成”；应展示“四类子单”，但其中“入职联系 / 劳动合同签订”按原条件命中后才生成。
2. “社保公积金办理”必须对所有入职提交单生成，不再按参保省份、城市、项目等条件决定是否生成。
3. 当前没有历史数据，业务上按“从现在开始一拆四”处理，不做历史一拆三迁移页面口径；但前端渲染仍应保留动态兜底，避免接口异常或旧测试数据导致白屏。
4. 杨杰账号当前不存在，前端不硬编码用户 ID；只展示“当前社保负责人 / 未配置负责人”，等账号创建后通过模块负责人配置接入。

### 0.2 dirty 已阅清除规则

当下游负责人打开子工单详情，或点击“确认已阅”后，该子工单当前轮的所有 dirty 标记清除。

前端表现：

- 未清除前：字段标红、顶部提示条、列表红点 / “有变更”标签。
- 负责人打开详情后：自动触发已阅清除；成功后红色 dirty 状态消失，并展示“已标记为已阅”。
- 自动清除失败时：保留“确认已阅”按钮，允许用户手动重试。
- 审计记录不在业务页面删除；如后端提供历史记录，仍可在操作日志中查看。

### 0.3 已完成子单退回权限

已完成子单的退回入口只给模块主管或系统管理员显示，普通办理人完成后不显示退回入口。

| 模块 | 普通办理人示例 | 已完成后可退回人 | 说明 |
|---|---|---|---|
| 劳动合同签订 | 杨纯 | 合同组主管江璐、系统管理员 | 普通合同办理人完成后不可退回 |
| 入职联系 | 毛雅妮 | 入离职 / 共享模块主管江璐、系统管理员 | 普通联系办理人完成后不可退回 |
| 数据录入 | 数据录入办理人 | 数据录入组长安娜祯、系统管理员 | 主管可退回已完成节点 |
| 社保公积金办理 | 后续配置的社保办理人 | 社保负责人杨杰、系统管理员 | 杨杰账号未存在时显示“未配置主管”，不开放给普通人 |

退回交互：

- 仅在“已完成”子单详情中展示“退回已完成节点”按钮。
- 点击后弹窗填写退回原因，原因必填，空白或纯空格禁止提交。
- 弹窗提示：退回后该节点需要重新办理，业务员可在所有已完成节点退回后重新修改并提交。
- 退回记录中展示退回人、退回时间、退回原因、节点名称。

### 0.4 社保批量完成备注必填

社保公积金办理批量完成时，备注必须填写。备注提示文案：

> 请填写本次批量完成说明，建议包含办理月份、社保 / 公积金基数、操作类型（新增 / 转入 / 补缴 / 无需办理等）及异常说明，便于后续追溯。

前端校验：

- 未填写备注不可提交。
- 备注长度建议 10-500 字；少于建议长度时可提示但不强制，最终长度限制以后端 DTO 为准。
- 批量完成结果要支持“全部成功 / 部分成功 / 全部失败”中文反馈。

## 1. 轻流式模块化搭建思路

本轮前端方案应参考轻流的“搭表单 + 配流程 / 模块 + 配字段权限”模式，避免把表格、字段、拆分规则写死在页面里。

### 1.1 核心原则

1. **表格不是写死列**：列表列、详情字段、导出字段尽量来自字段配置和模块配置。
2. **字段不是散落在代码里**：字段标题、类型、分组、必填、选项、来源、权限由字段配置驱动。
3. **拆分规则不是前端 if-else 堆叠**：入职联系、劳动合同的条件生成由拆分规则配置驱动；社保和数据录入为固定生成规则。
4. **权限不是按钮里临时判断**：字段权限、动作权限、主管退回权限由角色 + 模块 + 动作配置共同决定。
5. **中文展示统一从字典取**：模块码、状态码、权限码、动作码都只在字典层存在，业务页面不裸露英文 code。

### 1.2 管理员配置闭环

管理员后台建议形成以下配置路径：

1. **搭模块**：配置业务模块、子模块、模块中文名、模块负责人、模块主管、列表入口、可办理动作。
2. **搭字段**：配置字段编码、字段名称、字段类型、必填、选项、默认值、来源、所属分组、适用模块。
3. **配分组**：配置字段分组、分组排序、折叠面板、是否默认展开。
4. **配拆分规则**：配置哪些字段参与拆分判断，以及条件命中后生成哪些子单。
5. **配字段权限**：按角色 / 场景 / 模块设置“可编辑 / 只读 / 隐藏”。
6. **配办理动作**：配置接单、完成、批量完成、退回、确认已阅、导出等动作是否可见、是否需要原因 / 备注。

### 1.3 建议配置对象

| 配置对象 | 前端用途 | 关键字段 |
|---|---|---|
| 模块配置 | 菜单、列表标题、详情标题、模块卡片、筛选项 | 模块 code、中文名、业务域、负责人、主管、排序、是否启用 |
| 字段配置 | 动态表单、详情字段、表格列、导出字段 | 字段 code、中文名、类型、分组、必填、选项、来源、默认值 |
| 字段分组 | 表单分块、详情折叠面板、预览分区 | 分组 code、中文名、排序、默认展开 |
| 字段权限 | DynamicForm 渲染、详情隐藏、编辑态控制 | 角色、场景、模块、字段、权限中文态 |
| 拆分规则 | 发起页拆分预览、提交前校验说明 | 规则名称、条件字段、条件表达式、目标子模块、中文说明 |
| 模块负责人 / 主管 | 列表权限、办理入口、退回入口 | 模块 code、负责人、主管、AB 角、是否默认 |
| 办理动作配置 | 按钮显示、弹窗表单、批量操作 | 动作 code、中文名、适用状态、备注 / 原因是否必填 |

## 2. 入职发起页交互方案

目标文件：

- `frontend/src/pages/WorkOrders/New/index.tsx`

### 2.1 页面结构

1. 基础信息区：客户、业务员、员工基础信息等。
2. 动态字段区：按字段分组配置展示，不写死固定面板。
3. 拆分预览区：中文展示四类子单的生成结果。
4. 提交确认区：展示将生成的子单、未生成原因、负责人 / 未配置提示。

### 2.2 拆分预览必须中文展示四类子单

建议预览卡片顺序：

1. 数据录入：`固定生成`，状态文案“将生成”。
2. 入职联系：`按条件生成`，命中时“将生成”，未命中时“本次不生成”，并显示中文原因。
3. 劳动合同签订：`按条件生成`，命中时“将生成”，未命中时“本次不生成”，并显示中文原因。
4. 社保公积金办理：`固定生成`，状态文案“将生成”。

禁止展示：

- `data_entry`
- `onboarding_contact`
- `contract`
- `social_insurance`
- `true / false`
- `pending / skipped`

### 2.3 条件生成说明

入职联系、劳动合同签订仍按原来的业务条件生成。前端展示规则应由拆分规则服务返回，例如：

- “入职联系：满足‘需要入职联系 = 是’，将生成。”
- “入职联系：未满足原条件，本次不生成。”
- “劳动合同签订：满足‘企服发起劳动合同 = 是’，将生成。”
- “劳动合同签订：未满足原条件，本次不生成。”

如后端暂未返回规则说明，前端可以用中文兜底：

- “按原条件判断，具体以提交结果为准。”

### 2.4 提交成功弹窗

必须继续使用 `App.useApp()` 的 `modal`，不要使用 AntD 静态 `Modal.info / Modal.success`。

弹窗内容：

- 标题：“入职工单提交成功”。
- 子单列表：仅展示实际生成的中文子单。
- 社保说明：“社保公积金办理为所有入职工单必生成，负责人以后端配置为准。”
- 如社保负责人未配置：“社保负责人暂未配置，请管理员在模块负责人中补充。”

## 3. 字段配置与字段权限方案

目标文件：

- `frontend/src/pages/Admin/Fields/index.tsx`
- `frontend/src/services/fields.ts`
- `frontend/src/pages/Admin/FieldPermissions/index.tsx`
- `frontend/src/components/RolePermissionMatrix/index.tsx`

### 3.1 字段配置能力

字段配置页需要支持以下配置项：

| 配置项 | 前端中文名 | 说明 |
|---|---|---|
| `field_code` | 字段编码 | 仅管理员可见，用于接口和规则配置 |
| `field_label` | 字段名称 | 业务页面展示的中文名 |
| `field_group` | 字段分组 | 如“基础信息 / 合同信息 / 社保公积金信息” |
| `field_type` | 字段类型 | 文本、数字、金额、日期、月份、单选、多选、开关、附件、人员等 |
| `required` | 是否必填 | 动态表单校验依据 |
| `options` | 选项 | 单选 / 多选 / 下拉的中文选项 |
| `source` | 字段来源 | 业务员填写、系统生成、导入、下游回填、接口同步 |
| `split_rule_enabled` | 是否用于拆分判断 | 管理员用中文开关展示：“参与拆分判断 / 不参与拆分判断” |
| `sub_ticket_scope` | 适用子单范围 | 可选择数据录入、入职联系、劳动合同签订、社保公积金办理 |
| `sort_order` | 排序 | 控制表单、详情、列表中的展示顺序 |

### 3.2 字段分组

字段分组用于驱动发起页、详情页、子单详情页的布局。建议支持：

- 分组中文名。
- 分组说明。
- 排序。
- 是否默认展开。
- 适用模块。
- 分组内字段拖拽排序或数字排序。

示例分组：

1. 基础信息。
2. 员工信息。
3. 合同信息。
4. 入职联系信息。
5. 社保公积金信息。
6. 下游办理反馈。

### 3.3 字段权限三态中文展示

字段权限 UI 只展示中文三态：

| 技术枚举 | UI 中文 | 业务含义 |
|---|---|---|
| `visible` / `editable` | 可编辑 | 可查看且可修改 |
| `readonly` | 只读 | 可查看但不可修改 |
| `hidden` | 隐藏 | 不展示字段 |

注意：

1. 页面不能出现 `visible / readonly / hidden`。
2. 若后端历史数据仍返回 `masked`，前端统一显示“脱敏”；但本轮配置主界面以“可编辑 / 只读 / 隐藏”三态为主。
3. 权限矩阵中表头、筛选项、保存结果提示都必须中文。
4. 保存按钮仍需保留 P0-C2 修复：管理员改动后可点击，非管理员只读。

### 3.4 字段权限配置场景

建议至少覆盖：

- 发起页创建场景。
- 主工单详情查看场景。
- 主工单编辑场景。
- 子工单详情查看场景。
- 子工单办理场景。
- 社保批量完成场景。
- 已完成节点退回场景。

## 5. Dirty 标记与已阅清除交互

目标文件：

- `frontend/src/pages/MyDispatched/Detail/index.tsx`
- `frontend/src/pages/MyDispatched/index.tsx`
- `frontend/src/pages/WorkOrderPool/index.tsx`
- `frontend/src/pages/MyTodos/index.tsx`

### 5.1 列表表现

存在未读 dirty 时：

- 行标题或模块标签旁显示红点。
- 增加中文标签：“有字段变更”。
- Tooltip 展示：“业务员更新了字段，请打开详情核对。”

### 5.2 详情表现

详情页顶部提示条：

> 业务员更新了 3 个字段，请优先核对红色标记内容。打开详情后系统将自动标记为已阅。

字段表现：

- 字段区域左侧红色边框。
- 字段名旁显示“已变更”。
- 可展示变更摘要：原值、新值、修改人、修改时间。
- 用户无权查看的字段不展示 dirty 内容，也不泄露字段名。

### 5.3 自动清除

触发条件：

1. 当前用户是该子工单负责人 / 模块主管 / 管理员之一。
2. 子工单详情接口返回存在未读 dirty。
3. 页面完成首屏加载后触发清除。

成功反馈：

- 顶部提示条变为绿色或灰色提示：“已标记为已阅”。
- 字段红色高亮消失。
- 列表返回后红点消失。

失败反馈：

- 保留红色提示。
- 显示“确认已阅”按钮。
- 点击按钮重试清除。

## 6. 已完成子单退回交互方案

目标文件：

- `frontend/src/pages/MyDispatched/Detail/index.tsx`
- `frontend/src/services/dispatchedOrders.ts`

### 6.1 按钮显示规则

展示“退回已完成节点”按钮必须同时满足：

1. 子单状态为“已完成”。
2. 当前用户是系统管理员，或当前模块主管。
3. 后端动作权限返回允许退回。

必须隐藏按钮的场景：

- 普通办理人查看自己已完成的子单。
- 杨纯查看已完成劳动合同子单。
- 毛雅妮查看已完成入职联系子单。
- 业务员 / 只读角色查看子单。
- 社保主管杨杰账号未配置且当前用户不是管理员。

### 6.2 退回弹窗

弹窗字段：

- 子单名称：只读，中文展示。
- 当前状态：只读，显示“已完成”。
- 退回原因：必填 TextArea。
- 风险提示：退回后该节点需要重新办理，且业务员修改需等待所有已完成节点退回。

校验：

- 原因必填。
- 原因不能仅空格。
- 提交中按钮 loading，防止重复提交。
- 成功后刷新详情、列表、主工单状态和退回记录。

## 7. 社保公积金批量完成交互方案

目标文件：

- `frontend/src/pages/OnboardingModule/index.tsx`
- `frontend/src/pages/WorkOrderPool/index.tsx`
- `frontend/src/services/dispatchedOrders.ts`

### 7.1 可见范围

仅社保负责人、社保模块主管、系统管理员可见批量完成入口。业务员只能查看办理状态，不显示批量操作按钮。

杨杰账号暂未存在时：

- 不硬编码“杨杰”用户 ID。
- 模块负责人页显示“未配置社保负责人 / 主管”。
- 管理员可先看到配置提醒。
- 批量完成入口以后端权限为准，不因前端写死人员而错误开放。

### 7.2 批量完成弹窗

弹窗内容：

- 已选择数量。
- 子单范围：社保公积金办理。
- 完成日期：默认今天，可按后端要求只读或可选。
- 办理备注：必填。

备注占位文案：

## 13. 验收清单

### 13.1 业务员视角

- 新建入职工单时看到四类中文子单预览。
- 数据录入、社保公积金办理始终显示“将生成”。
- 入职联系、劳动合同签订按原条件显示“将生成 / 本次不生成”。
- 提交成功弹窗无英文 code，无 console error。
- 主工单详情只查看社保办理状态，不出现社保办理按钮。

### 13.2 下游负责人视角

- 打开子工单详情后 dirty 自动清除。
- 自动清除失败时可点击“确认已阅”。
- dirty 字段清除前有红色标记和顶部提示条。
- 清除成功后有“已标记为已阅”反馈。

### 13.3 模块主管 / 管理员视角

- 已完成子单可见“退回已完成节点”按钮。
- 退回原因必填。
- 退回后状态刷新、退回记录展示完整。
- 普通办理人杨纯、毛雅妮完成后不显示退回入口。

### 13.4 社保负责人视角

- 可进入社保公积金办理列表。
- 可多选社保子单批量完成。
- 批量完成备注必填。
- 备注提示包含月份、基数、操作类型等。
- 部分成功 / 部分失败有清晰中文反馈。

### 13.5 管理员配置视角

- 可配置模块、字段、字段分组、拆分规则、负责人 / 主管、办理动作。
- 字段权限只出现“可编辑 / 只读 / 隐藏”。
- 模块负责人中杨杰未创建时显示“未配置负责人 / 主管”，不显示空白。
- 拆分规则配置不强迫用户直接写 JSON，至少有中文说明和规则预览。
