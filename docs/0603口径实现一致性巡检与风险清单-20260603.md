## 5. QA重点回归清单

### 5.1 角色与菜单

| 角色 | 必测菜单/入口 | 通过标准 |
|---|---|---|
| 业务员 | 入职、离职、入职导入 | 可发起入职导入；不可见在职/待遇；不可见无权限 0 卡片。 |
| 业务组长 | 业务员入口 + 团队视角 | 可看团队范围；不可操作超出权限；不可见在职/待遇。 |
| 业务负责人 | 仪表盘 + 我的工单下团队工单/历史工单 | 不可发起导入/新建；团队/历史只读；dashboard 按权限隐藏。 |
| 杨纯 | 劳动合同新签/续签 | 只看合同类；第一期续签配置可后台保留但前台在职入口隐藏。 |
| 毛雅妮 | 入职联系/离职材料收集 | 只看联系/材料收集，不看合同、报岗、社保。 |
| 安娜祯 | 增员/减员报岗录入 | 只看报岗录入，不看社保、合同、联系。 |
| 傅倩雯 | 社保公积金增员/减员 | 只看社保增/减；不看入职联系、劳动合同、报岗录入。 |
| 江璐 | 杨纯 + 毛雅妮合集 | 我的工单各子菜单数据 = 杨纯 + 毛雅妮；不含社保、报岗、待遇。 |

### 5.2 API 与前后端兜底

1. `GET /api/dashboard/cards`：各角色不返回无权限模块 0 卡片；返回 `totalPending`、`monthPending`，历史遗留待办在月初不丢失。  
2. `GET /api/dashboard/order-type-matrix`、`GET /api/dashboard/leader-trend`：第一期不返回 `renewal/benefit`；后道只返回自己负责模块。  
3. `GET /api/dispatched-orders` / 我的工单相关 API：傅倩雯不可查到合同/联系/报岗；江璐不可查到 `social_insurance`、报岗、待遇。  
4. 导入 API：业务员/组长可导入入职；业务负责人和后道不可绕过前端直接导入。  
5. 直输 URL：在职、待遇、续签前台路径对业务/后道不可访问。

### 5.3 社保公积金状态流 E2E

| 场景 | 预期 |
|---|---|
| 社保增员/减员子单 `PENDING` 且 `acceptedAt == null` | 业务员修改/撤回/作废自由完成，不产生后道审批待办。 |
| 后道接单后 `acceptedAt != null` 或 `PROCESSING` | 业务员修改/撤回/作废需后道同意/审批或被提示走审批。 |
| 已完成 `COMPLETED` | 业务员不可直接修改/撤回/作废。 |
| 成功办理 | 办结。 |
| 明确业务数据问题 | 退回。 |
| 复办/等待 | 保持处理中；不新增社保/医保/公积金细分失败状态。 |
