## 三、未发布 P2 补强项说明

以下三项 **未在本轮 P0+P1 中实施**，原因明确，均需产品/Leader 范围决策后单独立项。

### 3.1 G-20 R4 "编辑必须走重新提交"产品语义强制

- **问题点**：当前业务员在 `processing` 态编辑工单时，调用 `update`，仅触发 `order.field_changed` 通知，工单 status 不回退，子工单也不重派。反馈文档 §"业务员涉及的操作"中提到"修改 / 重新提交"是两个动作，没有明确要求必须连贯触发；但 6 类流程中"情况 4"似乎暗示"修改后必须再次提交"。
- **为什么暂缓**：
  1. 产品口径不一致：列表已有"修改"按钮，详情页已有"重新提交"按钮（returned 态可见），强制连贯会改变现有交互。
  2. 重派可能影响后道已开始处理的工单（中断子工单进度）。
  3. 改动涉及 `work-order.service.ts` 状态机、子工单 dispatch 调度、通知模板，工作量大。
- **决策建议**：
  - 选项 A：保持现状，update 不改 status，后道凭 `order.field_changed` 通知决定是否回退处理。
  - 选项 B：编辑保存即 status → pending，子工单全部 reset → 重派。
  - 选项 C（中庸）：仅在编辑特定关键字段（劳动合同主体/起止/社保基数等）时强制重派，其他字段保持现状。
- **推荐**：先与产品 Sync 确认实际场景，再排期。

### 3.2 G-19 工单流程配置一期

- **范围未明**：文档 P4.2 仅说"管理员可完成各个工单的流程自定义配置"，未说明：
  1. 是只配置流程模板（节点 / 边 / 动作），还是同时配置办理人、SLA、字段权限？
  2. 是否兼容多版本（旧工单走旧流程）？
  3. 配置生效粒度（全局 / 客户级 / 工单级）？
- **数据库改动较大**：需新增 `workflow_definitions / workflow_nodes / workflow_edges / action_configs` 等表；且需要前端配置画布（流程图编辑器）。
- **决策建议**：建议产品先输出"工单流程配置一期需求文档"，明确范围和验收标准后再立项；本轮不做。

### 3.3 G-18 字段管理权限非管理员开放

- **决策项**：可授权角色范围（业务负责人？组长？）、可授权范围粒度（模块级？字段级？）、是否允许跨模块授权？
- **影响面**：涉及 `permissions` 表新增权限码、guard 改造、admin 端授权 UI 重新设计。
- **决策建议**：产品先输出"非管理员字段权限授权矩阵"，明确"哪个角色能配置哪些字段权限"后再立项；本轮不做。

> 以上三项 **不属于本轮代码修复范围**，不影响合规判定。
