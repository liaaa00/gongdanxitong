## 五、技术方案框架（如需新增任务）

### 5.1 前后端改动边界原则

| 改动类型 | 后端职责 | 前端职责 |
|---------|---------|---------|
| 状态机扩展 | 新增enum值 + migration | 更新STATUS_MAP常量 |
| 接口新增 | controller + service + DTO | services调用 + UI集成 |
| 权限调整 | guard + decorator + seed | 路由可见性 + 按钮禁用 |
| 通知分类 | biz_type + template seed | Tabs渲染 + 计数显示 |
| 数据清理 | migration + seed更新 | UI移除字段引用 |

### 5.2 优先级判定标准

| 优先级 | 定义 | 示例 |
|-------|------|------|
| **P0** | 阻断UAT，核心流程不可用 | 撤回/作废审批失败、导入后无子工单 |
| **P1** | 影响用户体验，但有workaround | 搜索字段缺失、批量办理按钮缺失 |
| **P2** | 增强功能，不影响主流程 | 表单排版优化、权限精细化 |

### 5.3 依赖关系识别规则

- **强依赖**：B任务需要A任务的代码产物（如DTO、enum、接口）
- **弱依赖**：B任务需要A任务的数据产物（如seed、migration）
- **并行**：A/B任务无共享代码/数据，可同时开发
