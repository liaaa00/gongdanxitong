## v1.2 · notification_templates 扩列 + 4 条 biz_type 新增（2026-05-11）

### 变更摘要

> 【架构变更 v1.2】notification_templates 表扩展两列：`default_channels` / `variables`，新增 4 条 `biz_type`。
> - 后端 Phase 6 运行前**必须**支持这两列；
> - 新 `biz_type` 不会破坏上游，但 Reviewer 检查时需认识；
> - 向下兼容：旧行自动补默认值，不中断线上。

### 涉及的工件

| 工件 | 变更 |
|------|------|
| `docs/数据库ER图.md` | 版本 v1.1 → v1.2；§4.9 `notification_templates` 新增两列；顶部加 v1.2 变更说明 |
| `docs/Phase6看板与通知设计.md` | §6.3 枚举表加两列（默认通道 / 变量清单），新增 4 行 |
| `backend/src/database/seeds/seed-notification-templates.ts` | 13 条模板完整 upsert，含 `defaultChannels` 与 `variables` |
| `docs/Phase2到Phase6_migration清单.md` | 第 1 项 `v1.2-notification-templates-extend-cols` |
| 本文件 | 追加 v1.2 条目 |

### 新增列详细

```sql
ALTER TABLE notification_templates
  ADD COLUMN default_channels JSONB NOT NULL DEFAULT '{"in_app":true,"email":false,"sms":false}'::jsonb,
  ADD COLUMN variables JSONB;
```

- `default_channels`：渲染后下发到哪些通道；运行时可由 `notifications.channel_override` 覆盖（若后续新增列）。`NotificationService.send()` 读不到该列会拒绝启动（fail-fast）。
- `variables`：JSON Schema Draft-2020-12；`send()` 前用 Ajv 校验；NULL → 不校验（兼容旧模板）。

### 新增 biz_type

| biz_type | 代表事件 | 备注 |
|----------|----------|------|
| `withdraw_resolved` | 撤回/修改决议（合并 approved/rejected） | 旧 `withdraw_approved` / `withdraw_rejected` 不再写入，但枚举保留 |
| `password_reset_by_admin` | 管理员重置用户密码 | 仅通知本人，临时密码只走 email |
| `assigned_as_supervisor` | 管理员任命主管 | 站内提醒即可 |
| `user_welcome` | 新用户激活 / 新建 | 首次登录入口 |

### 影响面

- **后端（必改）**：TypeORM entity `NotificationTemplate` 新增两列；`NotificationService.send()` 读取并校验；seed 重跑 upsert。
- **前端（轻微）**：通知列表卡片增加"通道徽章"可选展示；`bizType` → 图标表扩充 4 项。
- **QA**：e2e 新增 4 条覆盖，回归 `withdraw_approved/rejected` → `withdraw_resolved` 兜底路径。
- **运维**：migration 发布顺序为 Phase 6 启用前；`default_channels` 默认值已兜底，老数据零改动。

### 回滚预案

1. 先回滚后端版本（停用 `default_channels` / `variables` 的读取）；
2. 执行 `ALTER TABLE notification_templates DROP COLUMN default_channels, DROP COLUMN variables;`；
3. 枚举里 4 条新 `biz_type` 不删（只读无害）；
4. seed 回到 v1.1 版本文件（历史 commit 可恢复）。

### 验证清单

- [ ] `SELECT column_name FROM information_schema.columns WHERE table_name='notification_templates';` 返回 `default_channels` `variables`；
- [ ] `SELECT biz_type FROM notification_templates ORDER BY biz_type;` 返回 13 条（含 v1.2 新增）；
- [ ] `pnpm --filter backend test -- notification-service` 全绿；
- [ ] 前端 `/admin/notification-templates` 页面可编辑两列；
- [ ] `withdraw_approved` / `withdraw_rejected` 仍能被历史通知正确渲染。

## v1.1 · notifications 正式启用 + notification_templates 创建（2026-05-11）

### 变更摘要

> 【架构变更 v1.1】`notifications` 从"预留表"转正为 №20；新增 `notification_templates` (№21)；Phase 6 看板与通知模块上线。

### 涉及的工件

| 工件 | 变更 |
|------|------|
| `docs/数据库ER图.md` | 版本 v1.0 → v1.1；§4.8 / §4.9 两张表纳入正式表列 |

### 向后兼容

- `notifications.biz_type` 以字符串表示，未来扩枚举不破坏行。

## v1.0 · 初始 19 张表（2026-05-01）

### 变更摘要

- 建立核心域：`departments / users / roles / user_roles / customers / field_configs / field_permissions / dispatch_rules / module_handlers / field_supplement_rules / export_templates / work_orders / dispatched_orders / field_supplement_logs / withdraw_requests / withdraw_approvals / operation_logs / import_jobs`（18 张）+ 预留 `notifications`（彼时计作 №19）。
- 约定：所有主键 `bigserial`，时间列 `timestamptz`，枚举走 `varchar + CHECK`，JSONB 承接扩展字段。

### 关键设计决策

- 不使用 PG `ENUM` 类型——方便后续扩充；
- `work_orders.extra_data` 建 GIN 索引（支撑 Phase 3 基于 JSONB 的条件派发）；
- 操作日志 `operation_logs` **不建外键**——允许被引用实体删除后日志仍可读；
- 字段权限矩阵用 `(role_id, scene, field_code)` 三元组落到 `field_permissions`，与 `field_configs` 解耦。

### 影响面

项目起点；无向后兼容问题。
