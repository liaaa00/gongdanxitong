# D. 可执行审计建议

1. **保持 `test_cases_0518.md` 作为整改验收底线**：当前所有反馈编号均有 TC 覆盖，后续若新增 TC 建议放在补充文档或下一版用例中，避免扰动已评审用例。
2. **UAT 执行时新增 1 个管理员配置专场**：把 P4.1~P4.4 合并为一个 UAT 补充脚本，执行人建议为 QA + admin 账号，耗时约 30~45 分钟。
3. **UAT 执行时新增 3 个状态机审批分支**：覆盖 S2、S4、S5 的缺口，尤其是 `void_pending`、`withdraw_pending`、审批通过/拒绝、通知双方、后道待办取消/回滚。
4. **缺口优先级**：S2/S4/S5 属 P0，因为会影响真实工单流转正确性；P4.x 属 P1，因为验收用例已覆盖，UAT 可按配置专场补强。
5. **评审口径**：若开发实现未包含后道审批态（例如业务员作废直接终止），需由产品/架构确认是否偏离 `REMEDIATION_PLAN_0518.md` 的状态机设计，并同步调整验收口径。
