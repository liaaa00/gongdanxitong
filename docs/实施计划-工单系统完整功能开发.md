# 工单系统完整功能开发实施计划

## 📋 总览

本计划涵盖以下四大模块：
1. **省外工单改造**：独立子工单结构（无主工单）+ 菜鸟模板字段映射
2. **离职证明功能**：新增子工单类型 + 流转条件判断

## 一、省外工单改造（覆盖业务规则回归清单21.4节）

### 1.1 目标结构
- **入职管理** → 独立子工单：社保公积金增员
- **离职管理** → 独立子工单：社保公积金减员
- **在职管理** → 独立子工单：单项业务办理

**特点**：
- ✅ 无主工单，直接创建子工单
- ✅ 无拆单逻辑，一条导入记录 = 一个子工单
- ✅ 菜鸟项目派单模板导入，自动映射到工单系统字段

## 六、风险与确认点

### ⚠️ 需要用户确认的问题

1. **省外多人派单**：福建省派单给"羊晓焓/杨杰"，是轮流派单还是双人同时派单？
2. **证明模板格式**：Word模板变量占位符格式确认为 `{{变量名}}` 吗？
3. **后道范围切换器**：你提到"后道范围切换器只给后道看"，这个功能的具体需求是什么？是指：
   - 后道人员可以切换查看不同省份/区域的工单？
   - 还是指权限控制，业务员看不到后道视图？
4. **单项业务办理**：在职管理的"单项业务办理"子工单，是否需要与三级分类强绑定？还是可以独立发起？
5. **离职证明双条件**：如果"需要开具离职证明=否"，后续流程如何处理？是否直接跳过离职证明环节？

### ⚠️ 技术风险点

1. **字段映射复杂度**：菜鸟模板40个字段 → 系统20个字段，忽略20个字段，需要确保导入时不遗漏、不误映射
2. **三级分类联动**：前端Cascader组件需要处理空二级/三级分类的情况（如"企业开户"没有三级分类）
3. **模板导出性能**：Word模板填充需要考虑并发导出性能，建议使用队列异步处理
4. **种子数据幂等性**：现有种子数据不会更新已存在记录，需要手动清理旧数据或改为upsert逻辑
