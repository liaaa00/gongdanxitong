# 用户-角色分配功能测试报告

## 测试范围

针对前端用户-角色分配功能新增自动化测试，覆盖：

1. 用户列表是否展示「角色」列，并将多个角色以 Tag 形式展示。
2. 新建用户弹窗中角色多选控件是否可用，并加载全部角色选项。
3. 编辑用户时是否正确回填已有角色。
4. 保存新建/编辑用户时是否把 `role_ids` 转换为后端接口需要的 `roles` 数组。
5. 角色 mock 种子数据是否已从 6 个增加到 9 个。
6. mock 用户服务是否能持久化创建/更新时传入的角色数据。

## 新增测试文件

- `frontend/src/pages/Admin/Users/index.test.tsx`
  - 用户管理页 UI 与交互测试，共 5 条。
- `frontend/src/services/userRoleAssignment.test.ts`
  - 角色种子数据与用户 mock 服务测试，共 3 条。

### 前端完整单元测试

命令：

```bash
cd frontend
npm test
```

结果：存在 1 个既有用例失败。

- Test Files: 10 passed, 1 failed / 11
- Tests: 43 passed, 1 failed / 44
- 失败用例：`src/hooks/useFieldPermissions.test.ts > re-fetches when roles change`
- 失败原因：测试期望 admin 用户权限中存在字段 `name`，但当前 hook 对 admin 返回 `{ __ADMIN_ALL__: 'visible' }`。该失败与本次用户-角色分配专项测试无关。

```bash
cd frontend
npm run build
```

结果：通过。

## 结论

用户-角色分配功能的专项自动化测试已补齐并通过，验证了角色列展示、多选控件、编辑回填、保存 payload 转换、9 个角色种子数据和 mock 数据持久化。建议后续单独修复 `useFieldPermissions` 既有测试预期，或按当前 admin 默认权限逻辑更新断言。
