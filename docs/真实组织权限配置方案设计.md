## 1. 核心权限规则总览

本文档明确工单系统中三个最关键的权限规则，这些规则是用户最新权限口径的核心要求：

### 1.1 三大核心规则

| 规则编号 | 规则名称 | 涉及角色 | 核心要点 |
|---------|---------|---------|---------|
| **规则一** | 业务负责人只读权限 | 敖蕾、薛锟、余琴霞 | 可见全部业务工单，但**只读**，不参与任何办理/审批 |
| **规则二** | 共享团队负责人代理处理 | 江璐 | 对共享模块拥有**全模块可见+代理处理**权限，不受handler_id限制 |
| **规则三** | 公共池撤回审批 | 江璐、安娜祯 | 未接单子工单的撤回审批由模块负责人代审 |

### 1.2 规则优先级

当多个规则冲突时，按以下优先级处理：

1. **系统管理员（admin）**：最高优先级，可执行所有操作包括强制操作
2. **业务负责人只读规则**：强制只读，覆盖其他任何写权限
3. **共享团队负责人代理规则**：在共享模块内优先于handler_id判断
4. **公共池代审规则**：在handler_id为null时生效
5. **默认权限规则**：按角色和handler_id判断

## 2. 规则一：业务负责人只读权限

### 2.1 规则定义

**涉及角色**：
- `biz_gm`（总经理）：敖蕾
- `biz_gm_assistant`（总经理助理）：薛锟
- `biz_manager_assistant`（经理助理）：余琴霞

**数据范围**：
- 可见：全部业务工单（所有业务组发起的工单）
- 不可见：系统配置、其他用户的个人信息

**操作权限**：
- ✅ **允许**：查看工单详情、导出报表、查看看板、查看统计数据
- ❌ **禁止**：创建工单、修改工单、撤回工单、接单、完成、退回、补充字段、改派、审批撤回/修改申请

### 2.2 业务场景

业务负责人需要全局掌握业务进展，但不直接参与具体工单的办理和审批流程。他们的主要职责是：
- 监控全局业务数据和进度
- 导出报表进行分析
- 查看看板了解各组工作状态
- 不干预具体业务流程

### 2.3 实现要点

**后端实现**：
1. **查询过滤**：业务负责人查询工单时不做过滤（可见全部）
2. **写操作拦截**：在`WorkOrderGuard`和`DispatchedOrderGuard`中，对所有POST/PUT/PATCH/DELETE请求，如果用户角色包含`biz_gm`/`biz_gm_assistant`/`biz_manager_assistant`，直接返回403
3. **审批拦截**：在`WithdrawApprovalController`中，业务负责人不出现在审批人列表中

**前端实现**：
1. **按钮隐藏**：隐藏所有写操作按钮（创建、修改、撤回、接单、完成、退回、补充、改派、审批）
2. **表单只读**：工单详情页所有字段设置为只读模式
3. **菜单控制**：隐藏管理后台入口（仅admin可见）

**关键代码位置**：
- `backend/src/guards/work-order.guard.ts`
- `backend/src/guards/dispatched-order.guard.ts`
- `backend/src/modules/withdraw-requests/withdraw-approval.service.ts`
- `frontend/src/pages/WorkOrders/Detail.tsx`
- `frontend/src/pages/DispatchedOrders/Detail.tsx`

## 3. 规则二：共享团队负责人代理处理权限

### 3.1 规则定义

**涉及角色**：
- `shared_leader`（共享团队负责人）：江璐

**覆盖模块**（6个）：
1. `contract`（劳动合同签订）
2. `renewal_contract`（劳动合同续签）
3. `benefit_apply`（待遇申报）
4. `onboarding_contact`（入职联系）
5. `resignation_contact`（离职联系）
6. `resignation_cert`（离职证明）

**数据范围**：
- 可见：上述6个模块的**所有子工单**，无论handler_id是谁
- 不可见：数据录入模块（data_entry）的子工单

**操作权限**：
- ✅ **允许**：接单、完成、退回、补充字段、改派、导出
- ✅ **关键特性**：**即使子工单已分配给专员（杨纯/毛雅妮），江璐仍可代理处理**
- ❌ **禁止**：创建主工单、修改主工单、撤回主工单（这些是业务员的职责）

### 3.2 业务场景

江璐作为共享团队负责人，需要统筹管理合同和入离职两条业务线。具体场景包括：

**场景1：专员繁忙时代办**
- 杨纯手上有10个合同子工单待处理，客户催得急
- 江璐可以直接接手其中几个，帮助杨纯分担工作
- 操作：江璐在子工单列表看到"已分配给：杨纯"的工单，仍可点击"完成"按钮

**场景2：专员请假时接手**
- 毛雅妮请假3天，手上有5个入职联系子工单
- 江璐可以代理处理这些工单，不需要改派
- 操作：江璐直接完成这些工单，系统记录"江璐代理处理"

**场景3：跨专员改派**
- 某个合同工单分配给了杨纯，但实际更适合毛雅妮处理
- 江璐可以将工单从杨纯改派给毛雅妮
- 操作：江璐点击"改派"按钮，选择毛雅妮

### 3.3 实现要点

**后端实现**：
1. **查询过滤**：江璐查询子工单时，按`module_code IN (6个共享模块)`过滤，**不按handler_id过滤**
2. **写权限判断**：在`canHandleDispatchedOrder`方法中，如果用户是`shared_leader`且子工单属于6个共享模块，直接返回true，不检查handler_id
3. **操作日志**：记录江璐的代理操作，标记`is_proxy=true`和`original_handler_id`

**前端实现**：
1. **子工单列表**：江璐看到所有6个模块的子工单，包括已分配给杨纯/毛雅妮的
2. **操作按钮**：即使子工单显示"已分配给：杨纯"，江璐仍可看到"完成"/"退回"/"改派"按钮
3. **代理标识**：操作按钮旁显示"(代理处理)"提示，操作日志显示"江璐代理处理"

**关键代码位置**：
- `backend/src/services/permission-scope.service.ts` - `canHandleDispatchedOrder`方法
- `backend/src/modules/dispatched-orders/dispatched-orders.service.ts` - 查询过滤逻辑
- `frontend/src/pages/DispatchedOrders/index.tsx` - 子工单列表
- `frontend/src/pages/DispatchedOrders/Detail.tsx` - 子工单详情

## 4. 规则三：公共池撤回审批规则

### 4.1 规则定义

**适用场景**：
- 子工单的`handler_id`为`null`（未接单，处于公共池）
- 业务员发起撤回/修改申请时，该子工单需要审批

**代审人规则**：

| 模块线 | 代审人 | 角色 | 说明 |
|--------|--------|------|------|
| 共享模块（6个） | 江璐 | `shared_leader` | contract / renewal_contract / benefit_apply / onboarding_contact / resignation_contact / resignation_cert |
| 数据录入模块 | 安娜祯 | `data_entry_leader` | data_entry |

**备选方案**：
- 配置自动同意：`withdraw_auto_approve.enabled=true`
- 超时时间：`timeout_hours`（建议24小时）
- 范围：仅公共池子工单（`scope: "public_pool_only"`）

### 4.2 业务场景

**场景1：入职工单撤回（多子工单）**
- 业务员发起一个入职工单，自动派发3个子工单：
  - 合同签订：已分配给杨纯
  - 入职联系：未接单（handler_id=null）
  - 数据录入：已分配给安娜祯
- 业务员发起撤回申请
- 审批人确定：
  - 杨纯（合同子工单的handler）
  - **江璐（入职联系子工单的代审人）**
  - 安娜祯（数据录入子工单的handler）
- 审批结果：三方都同意才通过，任一拒绝则整体拒绝

**场景2：续签工单撤回（单子工单）**
- 业务员发起续签工单，派发1个子工单：
  - 合同续签：未接单（handler_id=null）
- 业务员发起撤回申请
- 审批人确定：
  - **江璐（合同续签子工单的代审人）**
- 审批结果：江璐同意即通过

**场景3：自动同意（可选）**
- 某个入职联系子工单在公共池超过24小时无人接单
- 业务员发起撤回申请
- 系统检测到超时，自动同意该子工单的撤回
- 操作日志记录：`action_type='auto_approve'`, `user_id=null`

### 4.3 实现要点

**后端实现**：
1. **审批人确定逻辑**（`WithdrawApprovalService.determineApprovers`）：
   - 遍历工单的所有未完成子工单
   - 如果`handler_id`不为null，该handler为审批人
   - 如果`handler_id`为null，按`module_code`查找代审人
   - 共享模块（6个）→ 江璐
   - 数据录入模块 → 安娜祯

2. **代审人查找**（`getProxyApprover`方法）：
   ```typescript
   private async getProxyApprover(moduleCode: string): Promise<string | null> {
     const sharedModules = ['contract', 'renewal_contract', 'benefit_apply', 
                            'onboarding_contact', 'resignation_contact', 'resignation_cert'];
     
     if (sharedModules.includes(moduleCode)) {
       // 共享模块 → 江璐
       const jianglu = await this.userRepo.findOne({ where: { username: 'jianglu' } });
       return jianglu?.id || null;
     }
     
     if (moduleCode === 'data_entry') {
       // 数据录入 → 安娜祯
       const annazhen = await this.userRepo.findOne({ where: { username: 'annazhen' } });
       return annazhen?.id || null;
     }
     
     return null;
   }
   ```

3. **自动同意检查**（`checkAutoApprove`方法）：
   - 读取系统配置`withdraw_auto_approve`
   - 检查撤回申请创建时间是否超过`timeout_hours`
   - 仅对`handler_id=null`的子工单自动同意
   - 记录操作日志`action_type='auto_approve'`

**前端实现**：
1. **审批列表**：江璐和安娜祯在审批列表中看到"公共池代审"标签
2. **代审标识**：显示"代审人：江璐"或"代审人：安娜祯"
3. **批量审批**：支持批量同意/拒绝多个公共池子工单

**关键代码位置**：
- `backend/src/modules/withdraw-requests/withdraw-approval.service.ts`
- `backend/src/entities/withdraw-approval.entity.ts` - `is_proxy`字段
- `frontend/src/pages/WithdrawApprovals/index.tsx`

```typescript
function isBusinessOwner(user: JwtUserPayload): boolean {
  return user.roles.some(r =>
```

**Guard拦截**：
```typescript
// WorkOrderGuard.ts
@Injectable()
export class WorkOrderGuard implements CanActivate {
  canActivate(context: ExecutionContext): boolean {
    const request = context.switchToHttp().getRequest();
    const user = request.user as JwtUserPayload;
    const method = request.method;
    
    // 业务负责人只读：拦截所有写方法
    if (this.permissionService.isBusinessOwner(user) && 
        ['POST', 'PUT', 'PATCH', 'DELETE'].includes(method)) {
      throw new ForbiddenException('业务负责人仅可查看工单，不可执行办理操作');
    }
    
    return true;
  }
}
```

### 5.2 共享团队负责人代理处理判定

**判定方法**：
```typescript
// PermissionScopeService.ts
function canHandleDispatchedOrder(user: JwtUserPayload, dispatchedOrder: DispatchedOrder): boolean {
  // 1. admin 全局权限
  if (user.roles.includes('admin')) return true;
  
  // 2. 本人被派单
  if (dispatchedOrder.handlerId === user.sub) return true;
  
  // 3. 共享团队负责人代理处理：不受 handler_id 限制
  const sharedModules = ['contract', 'renewal_contract', 'benefit_apply', 
                         'onboarding_contact', 'resignation_contact', 'resignation_cert'];
  if (user.roles.includes('shared_leader') && sharedModules.includes(dispatchedOrder.moduleCode)) {
    return true;
  }
  
  // 4. 数据录入组长代理处理
  if (user.roles.includes('data_entry_leader') && dispatchedOrder.moduleCode === 'data_entry') {
    return true;
  }
  
  return false;
}
```

**查询过滤**：
```typescript
// DispatchedOrderService.findAll
if (user.roles.includes('shared_leader')) {
  // 共享团队负责人：按 module_code 过滤，不按 handler_id
  qb.andWhere('d.module_code IN (:...sharedModules)', { 
    sharedModules: ['contract', 'renewal_contract', 'benefit_apply', 
                    'onboarding_contact', 'resignation_contact', 'resignation_cert']
  });
} else if (user.roles.includes('contract_specialist')) {
  // 专员：按 handler_id 过滤
  qb.andWhere('d.handler_id = :userId', { userId: user.sub });
}
```

**写操作鉴权**：
```typescript
// DispatchedOrderController.complete
@Put(':id/complete')
async complete(@Param('id') id: string, @User() user: JwtUserPayload) {
  const order = await this.service.findOne(id);
  
  // 鉴权：本人 or 共享负责人 or admin
  if (!this.permissionService.canHandleDispatchedOrder(user, order)) {
    throw new ForbiddenException('无权操作此子工单');
  }
  
  return this.service.complete(id, user);
}
```

### 5.3 公共池撤回审批代审逻辑

**审批人确定**：
```typescript
// WithdrawApprovalService.determineApprovers
async determineApprovers(withdrawRequest: WithdrawRequest): Promise<string[]> {
  const workOrder = await this.workOrderRepo.findOne({ 
    where: { id: withdrawRequest.workOrderId },
    relations: ['dispatchedOrders']
  });
  
  const approvers: string[] = [];
  
  for (const child of workOrder.dispatchedOrders) {
    if (child.status === DispatchedOrderStatus.COMPLETED) continue; // 已完成不参与审批
    
    if (child.handlerId) {
      // 已接单：节点处理人审批
      approvers.push(child.handlerId);
    } else {
      // 公共池：按模块代审
      const proxyApproverId = await this.getProxyApprover(child.moduleCode);
      if (proxyApproverId) {
        approvers.push(proxyApproverId);
      }
    }
  }
  
  return [...new Set(approvers)]; // 去重
}
```

**自动同意检查**：
```typescript
// WithdrawApprovalService.checkAutoApprove
async checkAutoApprove(withdrawRequest: WithdrawRequest): Promise<void> {
  const config = await this.configService.get('withdraw_auto_approve');
  if (!config?.enabled) return;
  
  const now = new Date();
  const createdAt = withdrawRequest.createdAt;
  const timeoutMs = config.timeout_hours * 3600 * 1000;
  
  if (now.getTime() - createdAt.getTime() < timeoutMs) return;
  
  // 超时：查找公共池未审批的子单
  const pendingApprovals = await this.approvalRepo.find({
    where: { 
      withdrawRequestId: withdrawRequest.id,
      status: ApprovalStatus.PENDING
    },
    relations: ['dispatchedOrder']
  });
  
  for (const approval of pendingApprovals) {
    if (!approval.dispatchedOrder.handlerId) { // 仅公共池
      approval.status = ApprovalStatus.AGREE;
      approval.approvedAt = now;
      approval.approverId = null; // 系统自动
      approval.comment = `系统自动同意（超时 ${config.timeout_hours}h）`;
      await this.approvalRepo.save(approval);
      
      // 记录操作日志
      await this.operationLogRepo.save(this.operationLogRepo.create({
        entityType: 'withdraw_approval',
        entityId: approval.id,
        userId: null,
        actionType: 'auto_approve',
        afterData: { status: 'agree', reason: 'timeout' },
        ipAddress: null
      }));
    }
  }
}
```

```tsx
  <Card>
    <div>模块：{dispatchedOrder.moduleCode}</div>
    {dispatchedOrder.handlerId && (
      <div>已分配给：{dispatchedOrder.handler.realName}</div>
    )}
    {canHandle && (
      <>
        <Button onClick={handleComplete}>
          完成 {dispatchedOrder.handlerId !== user.id && '(代理处理)'}
        </Button>
        <Button onClick={handleReassign}>改派</Button>
      </>
    )}
  </Card>
);
```

## 10. 常见问题FAQ

### Q1: 业务负责人能否查看子工单详情？
**A**: 可以。业务负责人可以查看全部业务工单及其子工单的详情，但所有字段都是只读模式，无法执行任何操作。

### Q2: 江璐能否改派已分配给杨纯的子工单？
**A**: 可以。江璐作为共享团队负责人，对6个共享模块拥有全模块可见和代理处理权限，包括改派操作。

### Q3: 如果入职工单的3个子工单都未接单，撤回审批由谁处理？
**A**: 
- 合同子工单：江璐代审
- 入职联系子工单：江璐代审
- 数据录入子工单：安娜祯代审

### Q4: 业务组长能否审批本组工单的撤回申请？
**A**: 不能。业务组长不参与撤回审批，审批仅由节点处理人或公共池代审人处理。

### Q5: 自动同意功能是否会覆盖已接单的子工单？
**A**: 不会。自动同意仅对`handler_id=null`的公共池子工单生效，已接单的子工单不受影响。

### Q6: 杨纯能否查看江璐已接单的合同子工单？
**A**: 可以查看，但只读。杨纯作为合同专员，只能操作分配给自己的子工单。

### Q7: 敖蕾能否通过API直接调用创建工单接口？
**A**: 不能。后端Guard会拦截所有业务负责人的写操作，返回403 Forbidden。

### Q8: 如何配置自动同意功能？
**A**: 在系统配置表中添加：
```json
{
  "withdraw_auto_approve": {
    "enabled": true,
    "timeout_hours": 24,
    "scope": "public_pool_only"
  }
}
```
