### 2.2 关键边界说明

- **admin vs biz_gm**：都能看全部数据，但 biz_gm 不能改系统配置、不能创建/修改/撤回/审批工单。前端管理后台入口仅对 `admin` 开放。
- **业务负责人（biz_gm 系）为全部业务工单只读角色**：敖蕾/薛锟/余琴霞可见全部业务工单 + 看板 + 导出，但**不参与任何工单办理/审批**。所有写接口（创建/修改/撤回/审批/接单/完成/退回/补充）在 `WorkOrderGuard` 层硬拦截返回 403。
- **biz_leader 双重身份**：组长在"作为业务员"时走业务员入口（发起/修改/撤回本人工单），在"作为组长"时查看本组数据。两种能力并存，不矛盾。
- **biz_leader 不参与审批**：组长对本组工单只有查看权，**不能审批撤回/修改**。审批走节点处理人（见 §7）。
- **biz_member 严格本人**：默认"仅本人发起"，**不开启**组内互读（v1.1 明确收紧）。
- **shared_leader（江璐）全模块可见 + 代理处理权限**：对共享团队模块（劳动合同签订/续签、入职联系/离职联系/离职证明等）拥有全模块可见权限，**即使子工单已分配给专员（杨纯/毛雅妮），江璐仍可代理处理**（接单/完成/退回/补充/改派）。实现方式：通过挂到一级部门 `SHARED`，自动含 `CONTRACT_TEAM` + `ONOFF_TEAM` 子部门；权限判定时 `shared_leader` 对这两条线的所有子工单拥有写权限，不受 `handler_id` 限制。
- **benefit_apply（待遇申报）归合同专员**：v1.0 误将其放入数据录入组，v1.1 按用户口径归入 `contract_specialist`（杨纯）。

## 4. 可见范围规则（列表查询过滤）

代码位置：`work-order.service.ts:244` 附近、`dispatched-orders.service.ts` 类似位置。现状只识别 `admin` / `manager` / 默认三档，需扩展。

**判定优先级（命中即返）：**

| 条件 | SQL 过滤 | 是否可写 |
|------|----------|----------|
| 含 `admin` | 无过滤 | 可写（含强制操作）|
| 含 `biz_gm` / `biz_gm_assistant` / `biz_manager_assistant` | 无过滤 | **只读**（接口层拦截所有 POST/PUT/DELETE/审批动作）|
| 含 `biz_leader_gX` | `department_id IN (本组 id)` **或** `created_by = user.sub` | 仅对 `created_by = user.sub` 的工单可写 |
| 含 `biz_member` | `created_by = user.sub` | 对本人工单可写 |
| 含 `shared_leader` | `department_id IN (SHARED 子部门 id)` **或** `dispatched_orders.module_code IN (合同+入离职模块)` | 子工单节点可写 + 公共池代审 |
| 含 `contract_specialist` | `dispatched_orders.handler_id = user.sub` **AND** `module_code IN ('contract','renewal_contract','benefit_apply')` | 被派节点可写 |
| 含 `onoff_specialist` | `dispatched_orders.handler_id = user.sub` **AND** `module_code IN ('onboarding_contact','resignation_contact','resignation_cert')` | 被派节点可写 |
| 含 `data_entry_leader` | `dispatched_orders.module_code = 'data_entry'` **或** `department_id IN (DATA_ENTRY id)` | 录入节点可写 + 组内派单 |

**实现建议**：新增 `PermissionScopeService`，签名：

```ts
interface VisibleScope {
  mode: 'all' | 'department_tree' | 'module' | 'self' | 'handler';
  readonly: boolean;
  departmentIds?: string[];
  moduleCodes?: string[];
  userId?: string;
}
resolveVisibleScope(user): VisibleScope[]   // 多角色取并集
canWriteWorkOrder(user, workOrder): boolean // 写能力判定
```

`biz_gm` 系的 `readonly: true`，所有写接口在 `WorkOrderGuard` 里直接 403。

## 7. 撤回 / 修改审批流程（v1.1 新增关键章节）

对应代码：`backend/src/modules/withdraw-requests/*`、`backend/src/entities/withdraw-{request,approval}.entity.ts`。

### 7.1 审批人确定规则

**核心原则：只由当前节点处理人审批。组长不参与审批。**

发起方向：只有工单 `created_by` 本人（业务员或组长以业务员身份）可以发起撤回/修改申请。

审批方向按工单子单状态分流：

| 场景 | 审批人确定逻辑 |
|------|----------------|
| 单子单工单（续签/离职联系等） | 当前节点 `dispatched_orders.handler_id` 对应的处理人审批（杨纯/毛雅妮/安娜祯 其一） |
| 入职多子单工单（onboarding 含合同 + 入职联系 + 数据录入） | **所有未完成子单**的 `handler_id` 都需要审批同意，任意一个拒绝即整体拒绝；已完成的子单不参与审批 |
| 公共池无人接单（`handler_id IS NULL` 的子单） | 按 §7.2 代审规则 |
| 系统管理员强制 | `admin` 可绕过所有节点直接通过/驳回（审计日志记录 `force=true`） |

### 7.2 公共池代审规则（明确版）

**场景**：当某子单 `handler_id IS NULL`（未接单，处于公共池）时，撤回/修改审批无法找到节点处理人。

**代审人按模块线兜底**：

| 模块线 | 代审人 | 角色 | 兜底策略 |
|--------|--------|------|----------|
| **共享模块**（contract / renewal_contract / benefit_apply / onboarding_contact / resignation_contact / resignation_cert） | **江璐** | `shared_leader` | 代替未接单子单完成审批 |
| **数据录入模块**（data_entry） | **安娜祯** | `data_entry_leader` | 代替未接单子单完成审批 |

**或配置自动同意**：见 §7.3。

**实现要点**：
- 查询 `dispatched_orders` 时，若 `handler_id IS NULL`，按 `module_code` 路由到对应代审人
- 代审人在审批列表中看到"公共池待审"标签，区分于"本人被派单"
- 代审操作写入 `withdraw_approvals` 时，`approver_id` 为江璐/安娜祯，`is_proxy=true` 标记代审

### 7.3 系统可配置自动同意

针对长期无人接单的公共池场景，新增系统配置项：

```json
{
  "withdraw_auto_approve": {
    "enabled": false,
    "timeout_hours": 24,
    "scope": "public_pool_only"
  }
}
```

- 默认 `enabled=false`（保留人工兜底）
- 启用后：子单无人接单且代审人超时未处理超过 `timeout_hours` 小时，系统自动同意该子单的撤回/修改
- 自动同意操作写入 `operation_logs`，`action_type='auto_approve'`, `user_id=null`
- 范围仅限 `public_pool_only`（不覆盖已接单的子单，防止跳过专员审批）

### 7.4 审批流程实现建议

```
[发起撤回/修改]
    │
    ▼
[查询工单所有未完成子单]
    │
    ├─ 有 handler_id 的子单 → 该 handler 审批
    ├─ handler_id IS NULL 的子单 → 走 §7.2 代审规则
    │                              └─ 超时未审 & auto_approve 开启 → 系统自动同意
    └─ admin 强制 → 跳过所有节点
    │
    ▼
[聚合结果：全部同意→APPROVED；任一拒绝→REJECTED；部分同意→PARTIAL]
    │
    ▼
[回写 withdraw_requests.status 并触发工单状态回滚]
```

`withdraw_approvals` 表每条记录对应"一个子单 × 一个审批人 × 一次审批结果"；主记录 `withdraw_requests.status` 在所有子单审批完成后聚合更新。

## 9. 风险与注意事项

1. **biz_gm 系只读强制**：仅靠前端隐藏按钮不够，后端 Guard 必须硬拦截所有写接口（含子单接单/完成/退回、撤回审批、字段补充等），防止通过 API 直调绕过。
2. **biz_leader 双重身份复杂度**：组长既是业务员又是组长，权限判定需要先判"是否本人工单"再判"是否本组"。单测要覆盖边界：组长查看别组工单（拒）、组长修改本组组员工单（拒，只能看）、组长修改自己发起的工单（允）。
3. **入职多子单审批**：全部未完成子单同意才通过，任一拒绝即拒绝。实现时要注意并发：两个处理人同时审批时的事务隔离（建议用 `SELECT ... FOR UPDATE` 锁主 `withdraw_requests` 记录）。
4. **存量 department_id 迁移**：全量 `BIZ` 需要按创建人拆到具体业务组，迁移脚本要在预发环境验证数据一致性。
5. **benefit_apply 归属变更**：v1.0 曾误挂到数据录入，v1.1 归合同专员。上线时要检查是否已有历史 `benefit_apply` 工单派给数据录入组，需批量改派或保留历史不动（建议保留，只改新派单逻辑）。
6. **公共池代审并发**：江璐可能同时代审很多公共池子单，前端需要批量审批 UI + 按模块线分组展示。
7. **admin 强制操作审计**：所有 `force=true` 的审批操作必须进 `operation_logs`，管理后台提供独立筛选入口。
8. **数据录入组员缺失**：真实表中只有安娜祯一人，无 backup。数据录入工单量一旦上来需立刻补人。
9. **密码首次强制修改**：`users` 表加 `password_reset_required BOOLEAN DEFAULT true`，登录拦截改密前禁止访问业务接口。

## 12. QA 复验关键确认点（v1.1 补充）

为便于 QA 最终验收，明确以下 4 个关键口径：

### 12.1 业务负责人为全部业务工单只读角色
- **角色**：`biz_gm`（敖蕾）、`biz_gm_assistant`（薛锟）、`biz_manager_assistant`（余琴霞）
- **数据范围**：全部业务工单
- **操作能力**：只读 + 看板 + 导出
- **明确禁止**：不参与任何工单办理（创建/修改/接单/完成/退回/补充/改派）、不参与任何审批（撤回/修改审批）
- **实现**：后端 `WorkOrderGuard` 对 `biz_gm` 系所有写接口返回 403；前端隐藏所有写按钮 + 管理后台入口

### 12.2 共享团队负责人江璐对共享模块拥有全模块可见和代理处理权限
- **角色**：`shared_leader`（江璐）
- **覆盖模块**：劳动合同签订（contract）、劳动合同续签（renewal_contract）、待遇申报（benefit_apply）、入职联系（onboarding_contact）、离职联系（resignation_contact）、离职证明（resignation_cert）
- **关键能力**：**即使子工单已分配给专员（杨纯/毛雅妮），江璐仍可代理处理**
- **具体操作**：接单/完成/退回/补充/改派/查看团队
- **实现**：权限判定时，`shared_leader` 对上述 6 个 `module_code` 的所有子工单拥有写权限，不受 `dispatched_orders.handler_id` 限制；查询时按 `module_code IN (...)` 过滤，不按 `handler_id = user.sub`

### 12.3 公共池无人接单的撤回/修改审批规则
- **场景**：子工单 `handler_id IS NULL`（未接单，处于公共池）
- **代审规则**：
  - **共享模块**（contract / renewal_contract / benefit_apply / onboarding_contact / resignation_contact / resignation_cert）→ **江璐代审**
  - **数据录入模块**（data_entry）→ **安娜祯代审**
- **或配置自动同意**：系统配置 `withdraw_auto_approve.enabled=true` 后，超过 `timeout_hours`（默认 24h）的公共池子单自动同意
- **实现**：查询 `dispatched_orders` 时，若 `handler_id IS NULL`，按 `module_code` 路由到对应代审人；代审操作写入 `withdraw_approvals` 时标记 `is_proxy=true`

### 12.4 业务组长不参与撤回审批，只看本组且可作为业务员发起/修改/撤回
- **角色**：`biz_leader_g1~g5`（沈文君/陈宇辰/高璐璐/刘程/余维维）
- **查看范围**：本组全部业务员工单（只读）
- **作为业务员**：可发起/修改/撤回本人工单
- **明确禁止**：**不参与撤回/修改审批**（组长不出现在任何审批人列表）
- **实现**：`WithdrawApprovalService` 确定审批人时，仅按 `dispatched_orders.handler_id` 或公共池代审规则，不因发起人所在部门的组长而增加审批节点

```ts
// PermissionScopeService.ts
function canHandleDispatchedOrder(user: JwtUserPayload, dispatchedOrder: DispatchedOrder): boolean {
  // 1. admin 全局权限
  if (user.roles.includes('admin')) return true;
  
  // 2. 本人被派单
  if (dispatchedOrder.handlerId === user.sub) return true;
  
  // 3. 共享团队负责人代理处理：不受 handler_id 限制
  const sharedModules = ['contract', 'renewal_contract', 'benefit_apply', 
                         'onboarding_contact', 'resignation_contact', 'resignation_cert'];
  if (user.roles.includes('shared_leader') && sharedModules.includes(dispatchedOrder.moduleCode)) {
    return true;
  }
  
  // 4. 数据录入组长代理处理
  if (user.roles.includes('data_entry_leader') && dispatchedOrder.moduleCode === 'data_entry') {
    return true;
  }
  
  return false;
}
```

### 13.3 公共池撤回审批代审逻辑

**审批人确定**（`WithdrawApprovalService.determineApprovers`）：
```ts
async determineApprovers(withdrawRequest: WithdrawRequest): Promise<string[]> {
  const workOrder = await this.workOrderRepo.findOne({ 
    where: { id: withdrawRequest.workOrderId },
    relations: ['dispatchedOrders']
  });
  
  const approvers: string[] = [];
  
  for (const child of workOrder.dispatchedOrders) {
    if (child.status === DispatchedOrderStatus.COMPLETED) continue; // 已完成不参与审批
    
    if (child.handlerId) {
      // 已接单：节点处理人审批
      approvers.push(child.handlerId);
    } else {
      // 公共池：按模块代审
      const proxyApproverId = await this.getProxyApprover(child.moduleCode);
      if (proxyApproverId) {
        approvers.push(proxyApproverId);
      }
    }
  }
  
  return [...new Set(approvers)]; // 去重
}

private async getProxyApprover(moduleCode: string): Promise<string | null> {
  const sharedModules = ['contract', 'renewal_contract', 'benefit_apply', 
                         'onboarding_contact', 'resignation_contact', 'resignation_cert'];
  
  if (sharedModules.includes(moduleCode)) {
    // 共享模块 → 江璐
    const jianglu = await this.userRepo.findOne({ where: { username: 'jianglu' } });
    return jianglu?.id || null;
  }
  
  if (moduleCode === 'data_entry') {
    // 数据录入 → 安娜祯
    const annazhen = await this.userRepo.findOne({ where: { username: 'annazhen' } });
    return annazhen?.id || null;
  }
  
  return null;
}
```

**自动同意配置**（`WithdrawApprovalService.checkAutoApprove`）：
```ts
async checkAutoApprove(withdrawRequest: WithdrawRequest): Promise<void> {
  const config = await this.configService.get('withdraw_auto_approve');
  if (!config?.enabled) return;
  
  const now = new Date();
  const createdAt = withdrawRequest.createdAt;
  const timeoutMs = config.timeout_hours * 3600 * 1000;
  
  if (now.getTime() - createdAt.getTime() < timeoutMs) return;
  
  // 超时：查找公共池未审批的子单
  const pendingApprovals = await this.approvalRepo.find({
    where: { 
      withdrawRequestId: withdrawRequest.id,
      status: ApprovalStatus.PENDING
    },
    relations: ['dispatchedOrder']
  });
  
  for (const approval of pendingApprovals) {
    if (!approval.dispatchedOrder.handlerId) { // 仅公共池
      approval.status = ApprovalStatus.AGREE;
      approval.approvedAt = now;
      approval.approverId = null; // 系统自动
      approval.comment = `系统自动同意（超时 ${config.timeout_hours}h）`;
      await this.approvalRepo.save(approval);
      
      await this.operationLogRepo.save(this.operationLogRepo.create({
        entityType: 'withdraw_approval',
        entityId: approval.id,
        userId: null,
        actionType: 'auto_approve',
        afterData: { status: 'agree', reason: 'timeout' },
        ipAddress: null
      }));
    }
  }
}
```

```tsx
      </>
    )}
  </Card>
);
```
