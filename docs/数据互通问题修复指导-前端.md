## 一、问题概述

当前前端存在两个关键问题：
1. **Mock模式判断逻辑错误**：导致系统错误进入Mock模式，数据存储在localStorage
2. **API配置为localhost**：其他电脑无法访问后端API

**目标**：
- 修复Mock模式判断逻辑，默认连接后端
- 配置API地址为服务器局域网IP
- 添加Mock模式提示，避免用户混淆

## 二、修复步骤

### 步骤1：修复Mock模式判断逻辑（核心）

```powershell
# 1. 打开Mock配置文件
cd D:\AI\SpeceAppDate\工单系统\frontend\src\services
notepad mock.ts
```

**修改内容**：
```typescript
// ❌ 修改前（错误逻辑）：
export const isMockMode = import.meta.env.VITE_USE_MOCK !== 'false';

// ✅ 修改后（正确逻辑）：
export const isMockMode = import.meta.env.VITE_USE_MOCK === 'true';
```

**问题分析**：
- 原逻辑：`!== 'false'` 意味着只要不是字符串 `'false'`，就进入Mock模式
- 当环境变量未定义时，`undefined !== 'false'` 为 `true`，错误进入Mock模式
- 新逻辑：只有明确设置 `VITE_USE_MOCK=true` 时才进入Mock模式
- 默认情况（未设置或设置为false）都会连接后端

### 步骤4：添加环境检测工具

```powershell
# 4. 创建环境检测工具
cd D:\AI\SpeceAppDate\工单系统\frontend\src\utils
notepad envCheck.ts
```

**创建新文件**：
```typescript
import { isMockMode } from '@/services/mock';

export interface EnvCheckResult {
  isValid: boolean;
  issues: string[];
  warnings: string[];
}

/**
 * 检查前端环境配置
 */
export function checkEnvironment(): EnvCheckResult {
  const issues: string[] = [];
  const warnings: string[] = [];

  // 检查Mock模式
  if (isMockMode) {
    warnings.push('系统处于Mock模式，数据不会同步到服务器');
  }

  // 检查API地址
  const apiUrl = import.meta.env.VITE_API_BASE_URL;
  if (!apiUrl) {
    issues.push('未配置API地址（VITE_API_BASE_URL）');
  } else if (apiUrl.includes('localhost') || apiUrl.includes('127.0.0.1')) {
    warnings.push('API地址配置为localhost，其他电脑无法访问');
  }

  // 检查环境变量
  if (import.meta.env.VITE_USE_MOCK === undefined) {
    warnings.push('未设置VITE_USE_MOCK环境变量');
  }

  return {
    isValid: issues.length === 0,
    issues,
    warnings,
  };
}

/**
 * 在控制台打印环境检查结果
 */
export function printEnvCheck(): void {
  const result = checkEnvironment();
  
  console.group('🔍 环境配置检查');
  console.log('Mock模式:', isMockMode ? '✅ 已启用' : '❌ 已禁用');
  console.log('API地址:', import.meta.env.VITE_API_BASE_URL || '未配置');
  console.log('环境变量VITE_USE_MOCK:', import.meta.env.VITE_USE_MOCK);
  
  if (result.issues.length > 0) {
    console.group('❌ 错误');
    result.issues.forEach(issue => console.error(issue));
    console.groupEnd();
  }
  
  if (result.warnings.length > 0) {
    console.group('⚠️ 警告');
    result.warnings.forEach(warning => console.warn(warning));
    console.groupEnd();
  }
  
  if (result.isValid && result.warnings.length === 0) {
    console.log('✅ 环境配置正常');
  }
  
  console.groupEnd();
}
```

**在 `main.tsx` 中调用**：
```typescript
// frontend/src/main.tsx
import { printEnvCheck } from './utils/envCheck';

// 在开发环境打印环境检查

  printEnvCheck();
}
```

## 四、常见问题排查

### 问题1：修改后仍在Mock模式

**症状**：
- 控制台显示 `isMockMode: true`
- 没有网络请求

**排查步骤**：
1. 确认 `mock.ts` 已修改并保存
2. 确认 `.env` 文件中 `VITE_USE_MOCK=false`
3. 重新构建：`pnpm build`
4. 清除浏览器缓存（Ctrl+Shift+Delete）
5. 硬刷新页面（Ctrl+F5）

**终极解决方案**：
```powershell
# 完全清理并重新构建
Remove-Item -Recurse -Force dist
Remove-Item -Recurse -Force node_modules/.vite
pnpm build
```

---

### 问题2：CORS错误

**症状**：
```
Access to XMLHttpRequest at 'http://192.168.26.66:3000/api/auth/login' 
from origin 'http://192.168.26.66:5173' has been blocked by CORS policy
```

**解决方案**：
1. 确认后端已配置CORS（参考《数据互通问题修复指导-后端.md》）
2. 检查后端 `main.ts` 中的 `origin` 配置是否包含前端地址
3. 重启后端服务

---

### 问题3：API请求404

**症状**：
```
GET http://192.168.26.66:3000/api/health 404 Not Found
```

**排查步骤**：
1. 确认后端服务已启动
   ```powershell
   # 在服务器电脑执行
   curl http://localhost:3000/api/health
   ```
2. 确认防火墙已开放3000端口
3. 确认API地址配置正确

---

### 问题4：其他电脑无法访问前端

**症状**：
- 电脑B访问 `http://192.168.26.66:5173` 超时

**排查步骤**：
1. 确认服务器电脑的防火墙已开放5173端口
   ```powershell
   netsh advfirewall firewall add rule name="工单系统前端" dir=in action=allow protocol=TCP localport=5173
   ```
2. 确认前端服务已启动
3. 在服务器电脑测试：`curl http://192.168.26.66:5173`
4. 检查网络连通性：`ping 192.168.26.66`

---

### 问题5：Vite开发服务器不监听局域网

**症状**：
- 前端只能在服务器电脑访问，其他电脑无法访问

**解决方案**：
```typescript
// vite.config.ts
export default defineConfig({
  // ...其他配置
  server: {
    host: '0.0.0.0',  // 添加这一行
    port: 5173,
    // ...其他配置
  },
});
```

重启开发服务器：
```powershell
pnpm dev
```

```powershell

Copy-Item -Recurse -Force dist/* C:\nginx\html\

# 3. 配置Nginx

```

**Nginx配置**：
```nginx
server {
    listen 80;
    server_name 192.168.26.66;
    
    # 前端静态文件
    location / {
        root html;
        index index.html;
        try_files $uri $uri/ /index.html;
    }
    
    # 后端API代理
    location /api {
        proxy_pass http://localhost:3000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    }
    
    # 文件上传
    location /uploads {
        proxy_pass http://localhost:3000;
    }
}
```

**启动Nginx**：
```powershell
cd C:\nginx
.\nginx.exe
```

**访问地址**：
- 前端：`http://192.168.26.66`
- API：`http://192.168.26.66/api`

## 七、Mock模式使用场景

Mock模式**仅适用于**以下场景：
1. ✅ 前端开发时，后端尚未就绪
2. ✅ 演示系统功能，无需真实数据
3. ✅ 前端单元测试
4. ✅ UI/UX设计评审

Mock模式**不适用于**：
1. ❌ 生产环境
2. ❌ 多用户协作
3. ❌ 数据需要持久化
4. ❌ 需要跨设备访问
