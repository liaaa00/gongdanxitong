## 7. FAIL / 缺陷清单（按严重度）

### BUG-01（低危·源码缺陷）submit 响应体返回事务提交前的过期主单快照

- **现象**：`POST /work-orders/:id/submit` 返回 201，`data.workOrder.status="draft"`，但子单数组已是 pending；事务提交后立即 GET 为 `processing`。功能不受损（DB 正确），但**响应体误导**：任何以 submit 响应为状态依据的客户端（含前端乐观更新）会短暂显示错误状态。
- **根因定位**：`backend/src/modules/work-orders/work-order.service.ts` `submit()` —— 事务内第 573/594 行两次 save 后，第 651 行 `return { workOrder: await this.loadDetail(workOrder.id), ... }` 而 `loadDetail`（1595 行）使用 `this.workOrderRepository`（**事务外默认 manager**），在 READ COMMITTED 下读不到未提交更新，返回提交前快照。resubmit 的同款写法（work-order-resubmit.service.ts:163）同样受影响。
- **复现**：登录业务员→创建→submit→观察响应 `data.workOrder.status` 与紧接 GET 差异。
- **建议**：loadDetail 接受可选 EntityManager 传入事务 manager；或返回事务内实体映射。**按铁律未修复，移交 Alex。**

### BUG-02（中危·状态机口径不一致）"PUT 修改→/resubmit" 后主工单停留 pending，处理人派单视图与常规 submit 不一致

- **现象**：returned 工单 PUT 补资料（→pending，写 salesperson_modify_resubmit 日志）→ `POST /:id/resubmit` 返回 201，子单全部重置 pending 且发出 dispatch_resubmit 通知，但**主单 status 仍 pending**（新鲜 GET 确认），而非 submit 路径的 processing。
- **根因定位**：`work-order-resubmit.service.ts` `resubmit()` PENDING 分支（75–99 行）执行 merge/applyChildren/notify 后**未将 workOrder.status 置为 PROCESSING 即 save**（对比 105 行起的 PROCESSING/RETURNED 分支亦仅置 PENDING——但那次重提场景语义不同）。
- **影响**：主单停在 pending 时若按业务规则"pending=待派发"，列表/看板 processing 计数不含该单；子单实际可接可办，最终办结仍可自动 completed（本次实测 data_entry 卡住仅因 CFG-01 账号问题）。属**可观测的口径不一致**，是否定性为缺陷需 Bob/Alex 确认产品意图；若 /resubmit PENDING 分支设计如此，应让 PUT 后状态直达 processing 或让 resubmit 写回 processing。
- **对照**：不 PUT 直接 submit（returned→processing）路径完全正常（Round2 R2b/R2c PASS）。**前端真实按钮流以哪条为准，建议结合 workOrders.ts:1127 resubmitWorkOrder 的调用页面复核。**

### CFG-01（配置缺陷·运营风险）data_entry 模块 beilun 唯一生效处理人 chenyujie 处于强制改密且无联系方式状态

- **现象**：本次生命周期用例中 data_entry 子单**无人可接**（处理人 403 "请先修改初始密码"），仅能 admin 代单；Round2 样本 R2d 因此停留 processing。
- **根因**：seed-users.ts 注释明示福保专员等"联系方式由管理员首次登录后补充，账号首次登录必须改密"；但 chenyujie 是**生产派单链路上的生效处理人**（module_handlers.is_active=true），强制改密 + 无手机邮箱 = 派单到达即死锁，除非管理员盯守。
- **建议**：管理员为其设置初始密码变更或由本人改密激活；QA 建议将"派单目标处理人已激活"纳入上线检查清单（docs/业务规则回归清单.md 口径）。**未替业务改动任何数据。**
