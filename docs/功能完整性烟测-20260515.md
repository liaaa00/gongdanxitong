#### FAIL 详情

1. **P0：撤回/作废审批接口 500，导致“作废后重复身份证放行”链路不可完成**
   - Network：`POST /api/withdraw-requests/7817a8fe-9512-4192-952f-b628f9cce981/approve` → `500`，响应 `code=1000`，traceId 示例：`req_492871b4-0324-4c63-944e-70569c6ab067`、`req_0feb6157-8800-47be-a1f0-badaea691368`。
   - 控制台/复现错误：用 dist 实体回滚复刻 `loadRequestForUpdate` 查询时，PostgreSQL 抛出 `FOR UPDATE cannot be applied to the nullable side of an outer join`。
   - 可能代码位置：`backend/src/modules/withdraw-requests/withdraw-request.service.ts` 的 `loadRequestForUpdate()`；该方法在 `.setLock('pessimistic_write')` 后同时 `leftJoinAndSelect` 多个可空关系，PostgreSQL 不允许对 outer join 的 nullable side 加 `FOR UPDATE`。
   - 影响：撤回申请任一审批人点击同意/拒绝均 500，主单无法进入 `withdrawn`，所以“作废后再传应放行”演示不可闭环。

2. **P0：`order.field_changed` 通知未扇出给发起人本人**
   - Network：`PUT /api/work-orders/c831edbc-8585-4b33-87f1-83f9180ec60e` → 成功；随后查询 `GET /api/notifications?bizType=order.field_changed&pageSize=100`，3 个下游用户各新增 1 条，发起人 `yaoyiping` 新增 0 条。
   - 控制台错误：无 5xx/白屏；属于业务断言失败。
   - 可能代码位置：`backend/src/modules/notifications/field-change.hook.ts:getNotificationTargets()` 当前把 `actorUserId` 过滤掉：`.filter((id) => id !== actorUserId)`。当“发起人本人作为业务员修改字段”时，发起人目标被排除。
   - 影响：与需求“3 个下游 + 创始人/发起人各收 1 条 `bizType=order.field_changed`”不一致。

#### 总评

**不可演示 / 不可交付验收。** 入职一拆三主链路、AB 角并发认领、默认密码首登强改密可演示；但撤回/作废审批 500 会阻断重复值“作废后放行”闭环，且变更通知中心缺少发起人通知，均属于 Stage A P0 主流程验收风险。
