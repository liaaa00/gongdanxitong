# 数据不互通问题根因分析报告

**报告日期**：2026-05-13  
**问题描述**：同一管理员账号在两台电脑登录，显示的数据不一致  
**严重程度**：🔴 P0 - 阻塞生产使用  
**分析人员**：架构师

---

## 一、问题现象

用户反馈：
- 使用管理员账号（admin）在两台不同电脑登录系统
- 两台电脑显示的工单数据完全不同
- 用户声称"已经用本地电脑作为服务器发散出去了"
- 确认不是权限问题，是数据隔离问题

---

## 二、架构诊断结果

### 🔍 诊断发现

经过对系统配置和代码的全面检查，发现**三层架构问题**导致数据不互通：

#### 1. **前端仍在Mock模式运行**（主根因）

**证据**：
```typescript
// frontend/src/services/mock.ts:1
export const isMockMode = import.meta.env.VITE_USE_MOCK !== 'false';
```

**问题分析**：
- 虽然 `frontend/.env` 配置了 `VITE_USE_MOCK=false`
- 但 `isMockMode` 的判断逻辑是 `!== 'false'`（字符串比较）
- 如果环境变量未正确加载，或者用户直接打开了 `dist/index.html`（生产构建），`import.meta.env.VITE_USE_MOCK` 可能是 `undefined`
- `undefined !== 'false'` 结果为 `true`，导致系统进入Mock模式

**Mock模式的影响**：
- 所有数据存储在浏览器的 `localStorage` 中
- 每个浏览器有独立的 `localStorage`，不同电脑之间完全隔离
- 即使连接同一个后端，前端也不会发送真实API请求

**验证方法**：
```javascript
// 在浏览器控制台执行
console.log('Mock模式:', import.meta.env.VITE_USE_MOCK);
console.log('实际判断结果:', import.meta.env.VITE_USE_MOCK !== 'false');
```

#### 2. **后端数据库配置为本地地址**（次要问题）

**证据**：
```env
# backend/.env
DB_HOST=127.0.0.1
DB_PORT=5432
```

**问题分析**：
- `127.0.0.1` 是本地回环地址，只能本机访问
- 其他电脑无法通过网络访问这个数据库
- 即使后端服务在运行，其他电脑也连不上数据库

**本机局域网IP**：
- 当前电脑的局域网IP：`192.168.26.66`
- 如果要让其他电脑访问，数据库应该监听 `0.0.0.0` 或 `192.168.26.66`

#### 3. **前端API配置为localhost**（次要问题）

**证据**：
```env
# frontend/.env
VITE_API_BASE_URL=http://localhost:3000
```

**问题分析**：
- `localhost` 只能访问本机的服务
- 其他电脑访问前端时，会尝试连接自己的 `localhost:3000`，而不是服务器电脑的后端
- 即使前端部署到服务器，其他电脑也无法正确访问后端API

---

## 三、根因总结

### 🎯 核心根因

**前端处于Mock模式，数据存储在浏览器localStorage，不同电脑之间完全隔离。**

### 📊 问题层级

```
问题层级：
┌─────────────────────────────────────────┐
│ L1: 前端Mock模式（主根因）               │
│     → localStorage隔离                   │
│     → 不发送真实API请求                  │
├─────────────────────────────────────────┤
│ L2: 数据库配置127.0.0.1（次要）          │
│     → 其他电脑无法访问数据库             │
├─────────────────────────────────────────┤
│ L3: 前端API配置localhost（次要）         │
│     → 其他电脑无法访问后端API            │
└─────────────────────────────────────────┘
```

### 🔄 数据流分析

**当前架构（错误）**：
```
电脑A:
  浏览器A → localStorage A → 数据集A
  
电脑B:
  浏览器B → localStorage B → 数据集B
  
结果：数据完全隔离 ❌
```

**期望架构（正确）**：
```
电脑A:
  浏览器A → HTTP请求 → 后端API → PostgreSQL数据库
  
电脑B:
  浏览器B → HTTP请求 → 后端API → PostgreSQL数据库
  
结果：共享同一个数据库 ✅
```

## 四、解决方案

### 🚀 方案A：快速修复（推荐，5分钟）

**适用场景**：立即解决问题，让两台电脑能看到相同数据

**步骤**：

1. **确保前端关闭Mock模式**
   ```powershell
   # 在服务器电脑（电脑A）执行
   cd D:\AI\SpeceAppDate\工单系统\frontend
   
   # 确认.env文件内容
   cat .env
   # 应该显示：
   # VITE_USE_MOCK=false
   # VITE_API_BASE_URL=http://localhost:3000
   ```

2. **修改前端API配置为局域网IP**
   ```powershell
   # 编辑 frontend/.env
   # 将 VITE_API_BASE_URL 改为服务器的局域网IP
   ```
   
   修改为：
   ```env
   VITE_USE_MOCK=false
   VITE_API_BASE_URL=http://192.168.26.66:3000
   ```

3. **修改后端数据库配置**
   ```powershell
   # 编辑 backend/.env
   # 将 DB_HOST 改为 0.0.0.0（监听所有网络接口）
   ```
   
   修改为：
   ```env
   DB_HOST=0.0.0.0
   DB_PORT=5432
   ```
   
   **注意**：如果PostgreSQL配置了只监听127.0.0.1，需要修改 `postgresql.conf`：
   ```conf
   listen_addresses = '*'  # 或 '0.0.0.0'
   ```

4. **配置PostgreSQL允许远程连接**
   ```powershell
   # 编辑 tools/pgsql16/data/pg_hba.conf
   # 添加一行（允许局域网访问）
   ```
   
   添加：
   ```conf
   host    all    all    192.168.26.0/24    md5
   ```

5. **重启服务**
   ```powershell
   # 重启PostgreSQL
   .\tools\pgsql16\stop-pg.ps1
   .\tools\pgsql16\start-pg.ps1
   
   # 重启后端
   cd backend
   pnpm start:dev
   
   # 重新构建前端（重要！）
   cd frontend
   pnpm build
   pnpm preview  # 或部署到Nginx
   ```

6. **在电脑B访问**
   ```
   浏览器打开：http://192.168.26.66:5173
   或：http://192.168.26.66（如果配置了Nginx）
   ```

---

### 🏗️ 方案B：生产级部署（推荐，30分钟）

**适用场景**：正式部署，支持多用户访问

**步骤**：

1. **使用Docker Compose部署**
   ```powershell
   cd D:\AI\SpeceAppDate\工单系统
   
   # 复制环境变量模板
   copy .env.example .env
   
   # 编辑.env，修改关键配置
   ```
   
   `.env` 配置：
   ```env
   # 数据库配置
   POSTGRES_HOST=postgres
   POSTGRES_PORT=5432
   POSTGRES_USER=ticket
   POSTGRES_PASSWORD=ticket123
   POSTGRES_DB=ticket_system
   
   # JWT密钥（必须修改）
   JWT_SECRET=your-production-jwt-secret-here
   JWT_REFRESH_SECRET=your-production-refresh-secret-here
   
   # 前端API地址（使用服务器IP）
   VITE_API_BASE_URL=http://192.168.26.66/api
   VITE_USE_MOCK=false
   ```

2. **启动服务**
   ```powershell
   docker compose up -d
   
   # 初始化数据库
   docker compose exec backend pnpm migration:run
   docker compose exec backend pnpm seed:run
   ```

3. **配置防火墙**
   ```powershell
   # 允许80端口（HTTP）和3000端口（API）
   netsh advfirewall firewall add rule name="工单系统HTTP" dir=in action=allow protocol=TCP localport=80
   netsh advfirewall firewall add rule name="工单系统API" dir=in action=allow protocol=TCP localport=3000
   ```

4. **访问系统**
   ```
   电脑A：http://192.168.26.66
   电脑B：http://192.168.26.66
   电脑C：http://192.168.26.66
   
   所有电脑看到相同数据 ✅
   ```

## 五、给后端和前端的修复指导

### 📋 后端工程师任务清单

1. **修改数据库监听地址**
   - [ ] 修改 `backend/.env`：`DB_HOST=0.0.0.0`
   - [ ] 修改 `postgresql.conf`：`listen_addresses = '*'`
   - [ ] 修改 `pg_hba.conf`：添加局域网访问规则
   - [ ] 重启PostgreSQL服务

2. **验证后端可访问性**
   - [ ] 在电脑B执行：`curl http://192.168.26.66:3000/api/health`
   - [ ] 应该返回 `{"status":"ok"}`

3. **配置CORS（如果需要）**
   ```typescript
   // backend/src/main.ts
   app.enableCors({
     origin: ['http://192.168.26.66:5173', 'http://192.168.26.66'],
     credentials: true,
   });
   ```

### 📋 前端工程师任务清单

1. **修复Mock模式判断逻辑**
   ```typescript
   // frontend/src/services/mock.ts
   // 修改前：
   export const isMockMode = import.meta.env.VITE_USE_MOCK !== 'false';
   
   // 修改后：
   export const isMockMode = import.meta.env.VITE_USE_MOCK === 'true';
   ```
   
   **理由**：
   - 默认应该是生产模式（连接后端）
   - 只有明确设置 `VITE_USE_MOCK=true` 时才进入Mock模式
   - 避免环境变量未加载时错误进入Mock模式

2. **修改API配置**
   ```env
   # frontend/.env
   VITE_USE_MOCK=false
   VITE_API_BASE_URL=http://192.168.26.66:3000
   ```

3. **添加Mock模式提示**
   ```typescript
   // frontend/src/App.tsx 或 BasicLayout
   useEffect(() => {
     if (isMockMode) {
       console.warn('⚠️ 当前处于Mock模式，数据存储在localStorage，不会同步到服务器');
       message.warning('当前处于演示模式，数据仅保存在本地浏览器');
     }
   }, []);
   ```

4. **重新构建**
   ```powershell
   cd frontend
   pnpm build
   ```

### 📋 测试工程师验证清单

1. **验证Mock模式已关闭**
   - [ ] 浏览器控制台执行：`console.log(import.meta.env.VITE_USE_MOCK)`
   - [ ] 应该显示 `false` 或 `undefined`（不是 `true`）

2. **验证API请求发送到后端**
   - [ ] 打开浏览器开发者工具 → Network
   - [ ] 登录系统，查看是否有 `/api/auth/login` 请求
   - [ ] 请求地址应该是 `http://192.168.26.66:3000/api/...`

3. **验证数据互通**
   - [ ] 电脑A：创建一个新工单
   - [ ] 电脑B：刷新页面，应该能看到电脑A创建的工单
   - [ ] 电脑B：修改工单状态
   - [ ] 电脑A：刷新页面，应该能看到电脑B的修改

4. **验证localStorage不再使用**
   - [ ] 清空localStorage：`localStorage.clear()`
   - [ ] 刷新页面，数据应该从后端加载，不受影响

## 七、总结

### ✅ 问题确认

- **主根因**：前端处于Mock模式，数据存储在localStorage
- **次要问题**：数据库和API配置为本地地址，其他电脑无法访问
- **影响范围**：所有非服务器电脑的用户

### 🎯 解决方案优先级

3. **长期改进**：添加环境检测、健康检查、配置验证机制

修复后：
- ✅ 所有电脑连接同一个后端和数据库
- ✅ 数据实时同步，无延迟
