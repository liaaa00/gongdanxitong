# 登录与后道列表 400 修复验收口径（2026-05-30）

## 背景

当前现象：登录或进入首页后，前端提示“请求超时，请检查网络后重试”，控制台出现：

- `Failed to load resource: the server responded with a status of 400 (Bad Request)`
- `dispatchedOrders.ts:412 [dispatched-orders] list request failed, showing empty table fallback AxiosError: Request failed with status code 400`

初步影响链路：`getDispatchedOrders` → `getDispatchedOrdersSafe` → `fetchAllPages` → `buildMatrixRowsFromListApis`。该链路用于 Dashboard 后道矩阵和后道列表兜底数据，不应把 HTTP 400 参数错误误判为网络超时。

## 本次修复目标

1. 修正请求参数或错误提示映射，使 HTTP 400 以参数/请求失败类错误呈现，不再显示为网络超时。
2. 保持 Dashboard 后道矩阵在后道列表接口异常时可降级展示，不白屏、不阻断登录后的首页渲染。
3. 保持后道列表 fallback 的空表兜底能力，但不得掩盖非静默场景下应提示给用户的真实错误。

## 禁止改动范围

本次修复属于稳定性与错误提示修复，不得改变以下内容：

- 不改变任何业务字段名、字段含义、字段来源和字段映射口径。
- 不改变工单状态枚举、后道节点枚举、订单类型枚举及统计归类规则。
- 不改变 Excel 导入模板、导出模板、模板字段顺序、字段标题和必填口径。
- 不改变表单字段、表单布局、必填项、校验规则、默认值和联动逻辑。
- 不改变权限、角色、菜单可见性、流程节点、流转动作和审批规则。
- 不改变 Dashboard 指标定义：总数、处理中、已完成、作废、完成率的统计含义保持不变。

## 功能验收标准

### A. 登录错误提示

- 当真实网络断开或浏览器报 `Network Error` 时，才提示网络连接失败类文案。
- 当请求超过前端超时时间或 Axios 返回 `ECONNABORTED/timeout` 时，才提示“请求超时，请检查网络后重试”。
- 当服务端返回 HTTP 400 时，不得提示“请求超时，请检查网络后重试”。应优先显示后端 `message`；无 message 时显示“请求失败 (400)”或等价的参数错误提示。
- 当服务端返回 HTTP 401 时，保持清理登录态并跳转登录页的既有行为。
- 当服务端返回 HTTP 403/404/5xx 时，继续沿用对应权限、资源不存在、服务端异常提示，不得统一吞成网络超时。

### B. Dashboard 后道矩阵

- 登录成功后进入 Dashboard，即使后道列表接口返回 400，页面也不能白屏或阻塞其他卡片/模块展示。
- 后道矩阵通过 safe fallback 降级时，可展示空矩阵/0 值，但控制台应能保留明确错误日志用于排查。
- 如果修复请求参数后接口正常返回，矩阵应按原有统计口径展示本月后道数据。
- 矩阵维度、标签、完成率公式、状态归类规则不得因本次修复改变。

### C. 后道列表 fallback

- `getDispatchedOrdersSafe` 仅用于允许静默降级的场景；异常时返回空分页，页面不崩溃。
- fallback 返回的分页信息应与请求页码、页大小一致或保持现有兼容口径，避免前端分页组件异常。
- 普通后道列表查询若不是静默场景，应向用户暴露真实错误提示，不得一律静默空表。
- 400 参数错误应推动修正前端传参或后端兼容，不应长期依赖空表 fallback 掩盖问题。

## 非功能验收标准

- 控制台错误应足够定位接口、状态码和调用链；不得出现误导性“网络超时”覆盖 400 的情况。
- 修复后不新增全局异常吞噬，不影响其它接口的错误提示行为。
- 修复后不引入额外请求风暴；Dashboard 分页拉取仍应受最大页数/页大小保护。
- Mock 模式与真实接口模式行为应保持兼容。

## 建议测试清单

1. 正常账号登录，确认不出现“请求超时，请检查网络后重试”的误提示。
2. 人为让 `/api/dispatched-orders` 返回 400，确认 UI 不白屏，Dashboard 可降级，错误提示不是网络超时。
3. 人为断网或关闭后端，确认仍显示网络连接失败/超时类提示。
4. 让后端返回带 `message` 的 400，确认优先显示后端 message。
5. 验证后道列表、Dashboard 后道矩阵、Excel 导入导出、相关表单字段与校验均无业务口径变化。

## 需求分析复核清单

- [ ] 修复点仅围绕 `/api/dispatched-orders` 列表参数兼容、分页参数规范化或错误提示分类，不夹带业务功能变更。
- [ ] 若后端放宽 DTO 参数校验，仅允许兼容前端既有查询参数；不得新增业务字段或改变查询语义。
- [ ] 若前端清洗参数，必须保留现有筛选含义；不得删除用户已填写的有效筛选条件。
- [ ] Dashboard 降级展示需有明确边界：允许后道矩阵为空或为 0，不允许影响登录态、导航、其它 Dashboard 卡片。
- [ ] 验收时需同时覆盖“接口正常”“接口 400”“真实网络异常/超时”三类场景，防止把所有异常归为同一提示。
- [ ] 回归范围至少包含登录、后道列表、Dashboard 后道矩阵、Excel 导入导出入口、相关表单保存校验。

## 结论

本次修复的验收重点是“错误分类准确 + 降级稳定 + 业务口径不变”。HTTP 400 是请求参数或服务端校验失败，不应被误报为网络超时。
