# 数据互通问题用户操作指南（2026-05-13）

## 一、这次问题的原因

你和同事登录的是同一个管理员账号，但两台电脑看到的数据不一样，核心原因不是权限问题，而是前端之前还可能进入 Mock 演示模式。

Mock 模式的数据只存在各自浏览器的本地缓存里：

- 你电脑导入/删除/新增的数据，只保存在你电脑浏览器里；
- 同事电脑也有一份自己的浏览器缓存；
- 两台电脑没有共同读写同一个后端数据库，所以看起来“同账号但数据不互通”。

本次已做快速修复：

1. 前端只有在明确配置 `VITE_USE_MOCK=true` 时才进入 Mock 模式；
2. 当前已配置为 `VITE_USE_MOCK=false`；
3. 前端 API 地址已改为本机局域网后端地址：`http://192.168.26.66:3000`。

> 注意：如果你的电脑 IP 后续变化，需要按本文步骤重新修改 `frontend/.env`。

## 二、确认本机 IP 地址

### 步骤 1：打开命令行

在作为服务器的那台电脑上操作，也就是你本地运行后端和前端服务的电脑：

1. 按键盘 `Win + R`；
2. 输入 `cmd`；
3. 回车。

### 步骤 2：查看 IP

在黑色窗口中输入：

```bat
ipconfig
```

然后回车。

找到类似下面这一行：

```text
IPv4 Address . . . . . . . . . . . : 192.168.26.66
```

这个 `192.168.26.66` 就是你这台电脑在局域网里的地址。

### 怎么判断应该用哪个 IP？

优先选择：

- `以太网` 或 `WLAN` 下面的 `IPv4 Address`；
- 通常长得像 `192.168.x.x`、`10.x.x.x`、`172.16.x.x`；
- 不要选 `127.0.0.1`；
- 不要选 `172.17.x.x` 这种虚拟网卡地址，除非你明确知道它是你的实际局域网地址。

本机当前检测到的可用 IP 是：

```text
192.168.26.66
```

## 三、修改前端配置

打开项目文件：

```text
D:\AI\SpeceAppDate\工单系统\frontend\.env
```

确保内容是下面这样：

```env
VITE_USE_MOCK=false
VITE_API_BASE_URL=http://192.168.26.66:3000
```

如果你的实际 IP 不是 `192.168.26.66`，请把第二行里的 IP 改成你自己 `ipconfig` 查到的 IPv4 地址，例如：

```env
VITE_API_BASE_URL=http://你的本机IP:3000
```

示例：

```env
VITE_API_BASE_URL=http://192.168.1.25:3000
```

修改 `.env` 后，必须重启前端服务，否则配置不会生效。

### 如果你是开发模式运行

在 `frontend` 目录下执行：

```bat

```

启动后，一般会看到类似：


请使用 `Network` 这一行给同事访问。

### 如果你是预览构建后的版本

先构建：

```bat

```

再启动预览服务：

```bat
npm run preview -- --host 0.0.0.0
```

## 五、后端服务也要允许局域网访问

后端必须运行在服务器电脑的 `3000` 端口，并且监听 `0.0.0.0` 或实际网卡地址。

你可以在服务器电脑上打开浏览器访问：

```text
http://localhost:3000/api/health
```

如果本机能访问，再让同事电脑访问：

```text
http://192.168.26.66:3000/api/health
```

如果同事电脑打不开，通常是防火墙或后端没有监听局域网地址。

## 六、同事应该怎么访问系统

同事不要再访问自己电脑上的 `localhost`。

同事电脑浏览器应该输入服务器电脑的前端地址，例如：

```text
http://192.168.26.66:5173
```

解释：

- `192.168.26.66` 是你的服务器电脑 IP；
- `5173` 是前端开发服务端口；
- 后端接口由前端配置指向 `http://192.168.26.66:3000`。

## 七、如何验证数据已经互通

请按下面步骤测试，不要跳步。

### 验证前准备

两台电脑都打开同一个地址：

```text
http://192.168.26.66:5173
```

两台电脑都登录同一个管理员账号。

### 测试 1：创建工单互通

1. 在你的电脑上进入“入职管理 / 主工单列表”；
2. 新建或导入一条测试工单；
3. 在同事电脑上刷新“主工单列表”；
4. 如果同事能看到你刚创建的工单，说明主工单数据已经互通。

### 测试 2：删除工单互通

1. 在你的电脑上删除刚才那条测试工单；
2. 在同事电脑上刷新列表；
3. 如果同事电脑上这条工单也消失，说明删除也已经写入同一个后端数据库。

### 测试 3：子工单互通

1. 在你的电脑上导入一条需要派发的入职工单；
2. 确认生成入职联系、劳动合同签订、数据录入子工单；
3. 在同事电脑上分别打开三个子工单列表；
4. 如果同事也能看到相同子工单，说明拆分派发数据已经互通。

## 八、非常重要：不要再使用 localhost 给同事访问

`localhost` 只代表“当前这台电脑自己”。

- 你电脑上的 `localhost` 是你的电脑；
- 同事电脑上的 `localhost` 是同事自己的电脑；
- 所以同事访问 `http://localhost:5173`，一定不是访问你的服务器电脑。

正确做法是统一访问服务器电脑 IP：

```text
http://192.168.26.66:5173
```

## 九、常见问题

### 1. 同事打不开 `http://192.168.26.66:5173`

可能原因：

- 前端服务没有用 `--host 0.0.0.0` 启动；
- Windows 防火墙拦截了 5173 端口；
- 两台电脑不在同一个局域网；
- IP 地址写错或服务器电脑 IP 变了。

处理方法：

1. 重新运行：

```bat
npm run dev -- --host 0.0.0.0
```

2. 检查服务器电脑 IP：

```bat
ipconfig
```

3. 确认同事访问的是最新 IP。

### 2. 页面能打开，但登录或数据接口报错

可能原因：

- 后端 3000 端口没有启动；
- `frontend/.env` 的 `VITE_API_BASE_URL` 还是 localhost；
- 防火墙拦截了 3000 端口。

处理方法：

1. 服务器电脑访问：

```text
http://localhost:3000/api/health
```

2. 同事电脑访问：

```text
http://192.168.26.66:3000/api/health
```

如果服务器能打开、同事打不开，重点检查防火墙。

### 3. 还是看到旧数据或两边不一致

可能是浏览器缓存中还有之前 Mock 模式的数据。

处理方法：

1. 退出登录；
2. 打开浏览器开发者工具；
3. 清理当前站点的 localStorage；
4. 重新登录；
5. 确认地址是 `http://192.168.26.66:5173`，不是 `localhost`。

### 4. IP 地址以后变了怎么办？

如果电脑换了网络、重启路由器或改用 Wi-Fi，IP 可能变化。

重新执行：

```bat
ipconfig
```

然后修改：

```text
frontend/.env
```

把：

```env
VITE_API_BASE_URL=http://旧IP:3000
```

改成：

```env
VITE_API_BASE_URL=http://新IP:3000
```

最后重启前端服务。

## 十一、最终判断标准

只要满足下面三点，就说明数据互通问题解决：

1. 你和同事访问同一个前端地址：`http://服务器IP:5173`；
