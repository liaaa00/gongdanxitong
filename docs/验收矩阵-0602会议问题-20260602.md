### E. 作废 / 重新提交　【P0｜backend_workflow 主，frontend 协同｜核心状态流改动，风险最高】

**这是与现状冲突最大的一项，需重点协调。**

**目标状态流**：
1. **重新提交合并撤销作废**：撤销作废动作并入"重新提交"，不再单独保留"撤销作废"按钮。
2. **已撤回、已退回、已作废子单都支持重新提交**（基线-3）。
3. 重新提交是**子工单级**，由发起人在子工单详情页操作；按钮与修改/作废并列。
4. 修改仅保存内容，**不自动重新提交**。
5. 重新提交后，子单重新流转到对应后道，状态进入正常处理中/待处理。
6. **撤回后作废不需要后道再次审批，直接作废**（VOID_PENDING → 直接 VOID）。

**现状冲突（探查确认）**：
- resubmit 现为**主工单级**（`work-order.controller.ts:93` → `WorkOrderResubmitService.resubmit`），仅 PENDING/PROCESSING/RETURNED 主工单可重提；**已撤回/已作废子单不能重提** → 与基线-3 冲突。
- 撤回后作废现需**二次审批**（`voidByCreator` → VOID_PENDING → 后道 `approveVoid`，`dispatched-order.service.ts:682-725`） → 与目标-6 冲突。
- 前端无独立"重新提交"按钮，退回/撤回走"修改"（`MyDispatched/Detail`）→ 需新增按钮。

**验收标准**：
1. 已退回子单：详情页有"重新提交"按钮，点击后子单回到对应后道，状态=待处理/处理中；通知后道。
2. 已撤回子单：详情页有"重新提交"按钮，行为同上。
3. 已作废子单：详情页有"重新提交"按钮，行为同上。
4. "修改"只保存 extraData，不触发流转（保存后状态不变）。
5. 撤回成功后发起人点"作废"→ 子单**直接进入 VOID 终态，无需后道审批**。
6. 后端兜底：非发起人调用子单 resubmit 被拒；状态不允许时返回明确错误码。

**涉及文件**：
- 后端：`dispatched-order.service.ts`（新增子单级 resubmit；`voidByCreator` 改直接作废）、`work-order-resubmit.service.ts`（评估复用还是新增子单路径）、`enums.ts:57-65`（状态流）。
- 前端：`MyDispatched/Detail/index.tsx:506-555`（新增"重新提交"按钮，门控 status ∈ {returned, withdrawn, void}）。
**接口约束（需 backend 先定，frontend 后接）**：
- 新增/复用接口：建议 `POST /api/dispatched-orders/:id/resubmit`（子单级），入参可携带修改后 extraData。**backend_workflow 须先确认接口路径与契约并同步给 frontend_permissions_ui，避免前端对错接口。**
- 重提后子单目标状态、是否重跑派发规则（命中后道）需明确：**演示口径=重新流转到原模块对应后道，进入 pending/processing**。
- 直接作废需保留审计日志（OperationLog），状态变更可追溯。
**风险**：状态流改动影响撤回/作废/退回三条链路与通知；务必补回归测试覆盖六个验收点。**若 06-03 前无法完整改造子单级 resubmit，降级口径：至少让"已退回"子单可重提（现状最接近），已撤回/已作废作为 P1 跟进——但需我和 Leader 确认降级。**

## 3. 依赖关系与实施顺序

```
①基线/分工矩阵(§1, 本文档) ──► ②B 后端 seed+scope+getAccessibleModules
                                      │
                  ┌───────────────────┼───────────────────┐
                  ▼                   ▼                   ▼
            ③A 前端菜单/守卫    ④F 导入类型筛选     ⑤H 我的工单数据范围
            (依赖②模块真相源)   (依赖②getAccessibleModules)

⑥E 子单级 resubmit + 撤回后直接作废 (后端先定接口契约 ──► 前端接按钮)
   └─► H 的子单详情页/只读详情页复用同一详情组件

⑦D 通知已读+筛选 (前后端独立, 低耦合)
⑧G 看板 totalPending+月筛选 (后端加字段 ──► 前端拆卡, 低耦合)
⑨C 命名 (展示层, 低耦合, 最后做)
```

**关键路径（必须串行）**：§1 矩阵 → B（getAccessibleModules 真相源）→ A/F/H 三者并行。
**可并行（低耦合）**：D、G、C、E 的后端部分可与 B 并行启动。
