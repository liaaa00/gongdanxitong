# 用户角色分配功能设计

## 1. 现状分析

### 1.1 用户管理页面 (`frontend/src/pages/Admin/Users/index.tsx`)

**已实现：**
- 用户列表展示（ProTable）：用户名、姓名、邮箱、手机、状态（启用/禁用）
- 新建/编辑弹窗（Modal + Form）：用户名、姓名、邮箱、手机、启用开关
- 操作：编辑、重置密码、启用/禁用、删除（仅 admin）

**缺失：**
- 列表不展示用户的角色信息（无 role 列）
- 新建/编辑弹窗中没有角色选择器
- 用户无法在管理页面看到或修改角色分配

### 1.2 用户服务 (`frontend/src/services/users.ts`)

- `UserItem` 接口已包含 `roles: { role_id: string; role_name: string }[]` 字段
- `createUser(data)` 和 `updateUser(id, data)` 已接受 `data.roles` 参数
- Mock 种子数据将 5 个用户全部设为角色 ID=3（业务员），硬编码

**结论：数据层已支持多角色，但 UI 从未传入 roles 数据。**

### 1.3 角色服务 (`frontend/src/services/roles.ts`)

- `getRoles()` 返回 `RoleItem[]`（含树形结构 children）
- `RoleItem` 包含：`id, code, name, level, description, is_active`
- 当前 Mock 种子仅 6 个角色（缺 `onboarding_team`, `data_entry_team`, `onboarding_supervisor`）
- 项目需求要求 9 个角色，需补齐种子

### 1.4 角色种子现状 vs 需求

| 角色 code | 角色名称 | 种子存在 |

| admin | 系统管理员 | ✅ |

## 2. UI 设计方案

### 2.1 用户列表增加「角色」列

在 ProTable 列定义中新增一列：

```
{ title: '角色', dataIndex: 'roles', key: 'roles', width: 240, hideInSearch: true,
  render: (_, record) => {
    if (!record.roles?.length) return <Tag>无角色</Tag>;
    return (
      <Space size={[0, 4]} wrap>
        {record.roles.map(r => (
          <Tag key={r.role_id} color="blue">{r.role_name}</Tag>
        ))}
      </Space>
    );
  },
}
```

### 2.2 新建/编辑弹窗增加「角色选择器」

在现有 Modal 表单中，于 `is_active` 启用开关上方增加：

```tsx
<Form.Item name="role_ids" label="角色" rules={[{ required: true, message: '请选择至少一个角色' }]}>
  <Select
    mode="multiple"
    placeholder="选择用户角色"
    options={roleOptions}  // 从 getRoles() 获取并扁平化
    optionFilterProp="label"
  />
</Form.Item>
```

**关键交互流程：**

1. **打开新建弹窗** → 调用 `getRoles()` → 填充 Select options → 角色字段为空
2. **打开编辑弹窗** → 调用 `getRoles()` → 填充 Select options → 用 `record.roles.map(r => r.role_id)` 回填已选值
3. **保存时** → 从 `role_ids` 构建 `roles: [{ role_id: x, role_name: y }, ...]` 传给 `createUser` / `updateUser`

### 2.4 Select options 数据来源

从 `getRoles()` 获取所有角色后，扁平化树形结构：

```ts
function flattenRoles(roles: RoleItem[]): { value: string; label: string }[] {
  const result: { value: string; label: string }[] = [];
  const walk = (list: RoleItem[], prefix: string = '') => {
    for (const r of list) {
      result.push({ value: r.id, label: prefix + r.name });
      if (r.children?.length) walk(r.children, prefix + '  ');
    }
  };
  walk(roles);
  return result;
}
```

选项按级别分组显示（可选优化，使用 `Select.OptGroup`）：
- 全局：系统管理员
- 管理层：项目经理
- 主管层：合同组主管、数据录入主管、入职联系主管
- 执行层：业务员、合同组、入职联系岗、数据录入岗

### 2.5 保存时数据转换

```ts
const onSave = async () => {
  const values = await form.validateFields();
  const { role_ids, ...rest } = values;

  // role_ids → roles
  const allRoles = await getRoles();
  const rolesMap = new Map(allRoles.map(r => [r.id, r]));
  const roles = (role_ids || []).map((rid: string) => ({
    role_id: rid,
    role_name: rolesMap.get(rid)?.name || '',
  }));

  const data = { ...rest, roles };
  if (editing) await updateUser(editing.id, data);
  else await createUser(data);
  // ... reload
};
```

## 5. 边界情况处理

| 场景 | 处理方式 |
|------|---------|
| 角色被删除但用户仍引用 | 角色列表实时从存储拉取，已删除的角色不再在 Select 中出现；用户保存时旧 role_id 被新的选择覆盖 |
| 用户选 0 个角色 | 表单校验 `required: true`，阻止提交 |
| 用户多次切换弹窗 | `destroyOnClose` 已配置，每次打开重新初始化表单值 |
