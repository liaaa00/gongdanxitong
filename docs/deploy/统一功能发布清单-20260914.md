## 执行顺序与放行标准

1. 修复前端银行卡条件：覆盖“工资单否/集约否”“工资单是/集约否”均必填，以及“集约是”可空，保持后端规则不变。
2. 收口旧省外写入口：核对前端 CRUD、导入及可能的兼容调用，防止 POST/更新/提交链继续生成旧结构工单；补真实路由/服务行为测试，不删除旧断言冒充修复。
3. 修复容器脚本白名单，核查命令依赖并构建镜像检查可用性；不执行生产数据修复脚本。
4. 对权限 stash 的差异按现行功能继续核对；certificate 旧迁移未确认必要性前不纳入。不能用“文件都存在”放行历史语义审核。
5. 修复后重新跑固定回归及构建；在隔离生产副本上验证迁移、旧数据保持，再做真实浏览器业务链（登录、权限、试用期、离职证明时间、门户提交、业务员审核修改、薪酬文字及附件）。记录真实请求及持久化结果；API 冒烟或 mock 不算浏览器验收。
6. 重建带逐文件哈希的候选包，更新发布/暂缓项及回滚方案；提供具体结果后再取得生产发布确认。
