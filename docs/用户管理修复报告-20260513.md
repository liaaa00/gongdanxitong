## 问题描述

用户反馈了用户管理模块的两个问题：

1. **角色选择重复**：创建用户时，角色下拉选项中出现重复的角色
2. **无法设置密码**：创建用户时没有密码输入框，无法为新用户设置密码

## 根因分析

### 问题1：角色选择重复

**文件**: `frontend/src/services/roles.ts`

**根因**: `flattenRoles` 函数在递归处理角色树时，没有去重机制。由于 `withChildren` 函数会为每个角色构建子角色关系，在某些情况下可能导致同一个角色被多次添加到结果数组中。

**代码位置**:
```typescript
// 原代码（第39-49行）
export function flattenRoles(roles: RoleItem[]): { value: string; label: string }[] {
  const result: { value: string; label: string }[] = [];
  const walk = (list: RoleItem[], prefix: string = '') => {
    for (const r of list) {
      result.push({ value: r.id, label: prefix + r.name });  // ❌ 没有去重
      if (r.children?.length) walk(r.children, prefix + '  ');
    }
  };
  walk(roles);
  return result;
}
```

### 问题2：无法设置密码

**文件**: `frontend/src/pages/Admin/Users/index.tsx`

**根因**: 创建用户的 Modal 表单中完全缺少密码输入字段。表单只包含：username、real_name、email、phone、role_ids、is_active，没有 password 字段。

**代码位置**: 第135-147行的 Modal 表单定义

## 修复方案

### 修复1：角色选择去重

**修改文件**: `frontend/src/services/roles.ts`

**修改内容**:
```typescript
export function flattenRoles(roles: RoleItem[]): { value: string; label: string }[] {
  const result: { value: string; label: string }[] = [];
  const seen = new Set<string>();  // ✅ 新增：用于记录已处理的角色ID
  const walk = (list: RoleItem[], prefix: string = '') => {
    for (const r of list) {
      // ✅ 新增：避免重复添加同一个角色
      if (!seen.has(r.id)) {
        seen.add(r.id);
        result.push({ value: r.id, label: prefix + r.name });
        if (r.children?.length) walk(r.children, prefix + '  ');
      }
    }
  };
  walk(roles);
  return result;
}
```

**效果**: 使用 `Set` 数据结构记录已处理的角色ID，确保每个角色只出现一次。

### 修复2：添加密码输入框

**修改文件**: 
1. `frontend/src/pages/Admin/Users/index.tsx`
2. `frontend/src/services/users.ts`

**修改内容**:

#### 2.1 前端表单添加密码字段

在 Modal 表单中，username 字段后添加密码输入框（仅在创建新用户时显示）：

```typescript
{!editing && (
  <Form.Item
    name="password"
```

**设计说明**:
- 仅在**创建新用户**时显示密码输入框（`!editing` 条件）

- 密码必填，最少6位
- 使用 `Input.Password` 组件，自动隐藏密码内容

#### 2.2 后端接口类型定义

**文件**: `frontend/src/services/users.ts`

更新 `UserItem` 接口，添加可选的 password 字段：


#### 2.3 Mock 数据处理

更新 `createUser` 函数，确保 Mock 模式下正确处理密码：


- 真实后端接口会正确处理密码加密和存储

## 后续建议

### 1. 后端密码处理

当前 Mock 模式下密码不存储。接入真实后端时，需确保：

- 后端接收 `password` 字段
- 使用 bcrypt 等算法加密存储
- 返回结果中不包含密码字段
- 实现密码强度校验（大小写、数字、特殊字符等）

### 2. 密码重置功能

当前"重置密码"按钮功能简单。建议增强：

- 重置为随机密码并通过邮件/短信发送给用户
- 或者发送重置链接，让用户自行设置新密码
- 记录密码重置日志

### 3. 角色管理优化

当前角色树结构可能存在循环引用风险（如 id=4 的 parent_role_id=5，而 id=5 的 parent_role_id=2）。建议：

- 在 `withChildren` 函数中添加循环检测
- 限制角色树的最大深度
- 提供角色关系可视化工具

### 4. 表单体验优化

- 添加"生成随机密码"按钮
- 密码强度指示器（弱/中/强）
- 角色选择支持搜索和分组显示
