# Phase 1 测试策略

> ⚠️ 当前演示口径（2026-06-03）：所有 seed/演示账号默认密码统一为 `123456`；`admin123` 是历史旧口径，会返回 401，不可用于演示。本文下方如出现 `admin123`，仅为历史记录/旧脚本背景，不代表当前可用密码。

## 1. 目标

Phase 1 的测试目标是验证入职工单系统基础骨架具备继续开发的质量基线：

- Docker Compose 可一键拉起 PostgreSQL、backend、frontend、Nginx，且 `docker compose config` 结构校验通过。
- PostgreSQL 16 迁移可重复执行，核心 19 张表、关键索引与约束符合架构设计。
- Seed 数据完整：11 个角色、5 个部门、54 个入职字段配置、4 条 onboarding 派发规则、字段权限矩阵、`admin/admin123`。
- 后端 NestJS 基础框架、统一响应 `{code,data,message,traceId}`、JWT 认证、`@Public`、`@Roles`、守卫链路可用。
- 前端 React + Ant Design Pro 基础布局、登录页、权限路由、刷新保持与退出登录可用。

## 2. Phase 1 测试范围

### 2.1 冒烟范围

| 模块 | 冒烟点 | 验证方式 |
|---|---|---|
| Docker Compose | `docker compose config` 通过，`docker compose up -d` 可启动所有服务 | `tests/smoke-test.ps1` |
| PostgreSQL | 容器健康检查通过，数据库可连接 | `tests/smoke-test.ps1`、`tests/verify-seed.ts` |
| Backend | `/api/health` 或部署约定 health endpoint 返回 200 | `tests/smoke-test.ps1` |
| Frontend/Nginx | Nginx 暴露端口返回 200/3xx，前端 SPA 可加载 | `tests/smoke-test.ps1` |
| Auth | `admin/admin123` 登录返回 JWT，响应符合统一响应结构 | `tests/smoke-test.ps1`、`backend/test/auth.e2e-spec.ts` |
| Seed | 角色、部门、字段、派发规则、权限矩阵、admin 密码正确 | `tests/verify-seed.ts` |

### 2.2 集成范围

| 模块 | 集成验证点 |
|---|---|
| 数据库迁移 | 19 张表存在；`work_orders.extra_data` 使用 JSONB；后续阶段需补充 GIN 索引与唯一约束验证 |
| Seed | 11 角色、5 部门、54 字段、4 派发规则、字段权限 scenario=`main`/`dispatched:<module_code>` |
| 认证 API | 登录、获取当前用户、刷新 token、修改密码、登出；响应均校验 `{code,data,message,traceId}` |
| 权限守卫 | 未登录 401；`@Public` 路由放行；`@Roles` 不满足时 403；一人多角色时任一角色满足即可访问 |
| 前端登录流程 | 登录成功、登录失败、刷新后登录态保持、退出登录 |
| 权限路由 | 未登录访问业务页跳转登录；无权限访问后台页显示 403 |

### 2.3 暂不覆盖项

Phase 1 只验证基础骨架，不覆盖以下业务闭环：

- 入职主工单创建、提交、DispatchEngine 派发、子工单接单/完成。
- FieldPermissionService 对工单 `extra_data` 的字段级过滤和脱敏实际业务数据验证。
- Excel 导入、AI 字段映射、错误报表导出。
- 字段补充回流、撤回审批、退回重提。
- StorageAdapter 附件上传/下载、导出模板、看板、站内通知。
- 大数据量性能测试、并发压测、安全渗透测试。

上述内容将在 Phase 3 之后进入主测试范围。

## 3. 测试金字塔

Phase 1 推荐覆盖比例：

| 类型 | 占比 | 目标 |
|---|---:|---|
| 单元测试 | 45% | 覆盖 AuthService、JwtStrategy、RolesGuard、配置解析、密码加密校验等纯逻辑 |
| 集成测试 | 40% | 覆盖认证 API、数据库 seed、迁移、守卫与装饰器组合行为 |
| E2E/冒烟测试 | 15% | 覆盖 Docker 一键启动、前端登录主路径、真实 HTTP 登录链路 |

说明：Phase 1 业务逻辑少，测试重心放在“骨架可运行、认证链路可用、基础数据可信、架构约束不偏离”。后续 Phase 业务复杂度提高后，E2E 比例逐步增加。

## 4. 环境策略

| 环境 | 用途 | 数据要求 |
|---|---|---|
| 本地开发环境 | 开发自测、快速调试 | 可重复 reset + migration + seed |
| CI 环境 | PR 自动测试 | 每次全新 PostgreSQL，执行 migration + seed |
| 验收环境 | Phase 交付验收 | 使用默认 admin 账号和少量演示用户 |

所有测试通过环境变量配置连接信息，避免写死端口和密码。

## 5. 测试数据策略

- 默认 admin：`admin / admin123`，用于 Phase 1 验收；如实现“首登强制改密”，自动化测试需识别该状态并记录。
- seed 验证必须检查：
  - 11 个默认角色。
  - 5 个默认部门。
  - 54 个 onboarding 字段配置。
  - 4 条 onboarding 派发规则。
  - 字段权限矩阵包含 `main` 与 `dispatched:<module_code>` 场景。
  - admin 密码可用 bcrypt 校验。
- 自动化测试修改密码后必须恢复为 `admin123`，避免影响后续脚本。

## 8. Phase 1 出口准则

满足以下条件才建议进入 Phase 2：

- Docker Compose 结构校验和冒烟测试通过。
- 数据库迁移和 seed 验证通过。
- 后端认证 E2E 测试通过或仅存在已确认的非阻塞问题。
- 前端登录与权限路由手工验收通过。
- README、部署说明和已知问题清单已更新。
- 无 P0 阻塞问题；所有 P1/P2 问题已记录负责人和复测方式。
