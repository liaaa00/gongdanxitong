# 业务规则回归清单

> 目的：把已经确认过的业务规则固化在项目内，避免后续修改时反复破坏旧规则。AI 或开发人员每次改动前必须先阅读本文件。

## 0. 规则优先级

本清单用于保护用户本次没有要求改变的旧规则，不用于压过用户最新明确要求。

优先级：

1. 用户当前最新明确要求。
2. 本清单中未被本次要求改变的既有规则。
3. Git commit、测试和历史文档。
4. AI 对话记忆或推断。

如果用户最新要求与本清单冲突，必须：

1. 明确指出冲突点。
2. 确认或判断用户是否明确要求覆盖旧规则。
3. 同步更新代码、测试、本清单。
4. 追加记录到 `docs/AI修改记录.md`。
5. 跑固定回归测试，确保未被覆盖的规则不被误伤。

## 1. 工单状态口径

系统统一使用以下 9 个子工单状态，页面筛选项不得随意新增、合并或改名：

1. 未接单：`pending`
2. 已接单：`processing`
3. 修改审批中：`modify_pending`
4. 撤回审批中：`withdraw_pending`
5. 作废审批中：`void_pending`
6. 已完成：`completed`
7. 已作废：`void`
8. 已撤回：`withdrawn`
9. 已退回：`returned`

注意：
- 页面筛选中不得再显示“未接单/已接单”这种合并选项。
- 单独筛选“未接单”只查 `pending`；单独筛选“已接单”只查 `processing`。
- 旧参数 `pending,processing` 可兼容，但不能作为页面显示选项。

## 2. 月份统计口径

工单流转统计按工单流转月份计算，不按完成时间计算。

当前列表/统计月份口径：
- 子工单列表的 `orderMonth`：按 `dispatched_at`，没有派发时间时按 `created_at`。
- 我的已办：按 `orderMonth`，不默认按 `completed_at`。
- 历史工单：按 `orderMonth`。
- 入职/离职主工单列表：默认当前月，可切换历史月份。
- 入职/离职子工单页面：默认当前月，可切换历史月份。

禁止事项：
- 不得把“我的已办”默认改回按完成时间 `completed_at`。
- 不得让 5 月派发/创建、6 月完成的工单默认归到 6 月已办统计。

## 3. 仪表盘口径

仪表盘体现工单最终流转状态：

- 未办结包含：未接单、已接单、修改审批中、撤回审批中、作废审批中、已撤回、已退回。
- 已完成：`completed`。
- 已作废：`void`。
- 当月工单总数 = 未办结 + 已完成 + 已作废。

后道仪表盘五项名称需与业务员仪表盘一致：
- 本月工单总数
- 单月待处理 / 本月待处理（按页面当前约定展示）
- 总待处理
- 本月已完成
- 本月已作废

## 4. 角色菜单矩阵

> 2026-08-07 覆盖说明：`我的工单`、`团队工单`、`历史工单`及其聚合列表入口已整体废除；本清单其他章节中引用这些入口的旧菜单、筛选、批量操作和导航记忆规则不再执行。子工单从入职、离职、在职等业务模块进入，消息通知仍可打开有权访问的子工单详情。

菜单可见性以 `frontend/src/config/routeVisibility.ts` 和 `frontend/src/layouts/BasicLayout.tsx` 为准。

- 北仑侧栏按“入职管理、在职管理、离职管理”分组，并按角色和实际模块权限收窄子菜单。
- 省外侧栏与北仑保持同级分组：入职管理下为“社保公积金增员”，离职管理下为“社保公积金减员”，在职管理下为“单项业务办理”。
- `我的工单` 聚合分组对管理员和普通角色均不显示；权限中心、旧缓存和历史书签不得重新开放。
- 系统唯一登录入口为 `/login`；账号密码校验不得依赖客户端选择或登录入口传入业务范围。登录成功后读取账号数据库 `businessScope` 自动跳转：`beilun` 进入 `/dashboard`，`out_of_province` 进入 `/out-of-province/increase`；历史 `/zhejiang-login` 仅重定向 `/login`，不得渲染第二登录页。
- 业务前端账号固定使用账号配置的业务范围；允许切换范围的账号使用“北仑/省外”业务范围控件。
- 管理员可看全局数据和管理后台；主工单列表默认 100 条/页。
- 后道普通模块列表仍按授权模块、实际处理人/主管配置和既有数据范围展示，不因菜单重排扩大权限。

## 5. 数据范围规则

- 合同模块保持团队认领模式；具备 `contract_specialist`、`labor_contract_member` 或 `contract_team` 角色的有效处理人，可查看合同模块全部相关子工单（包括历史上由其他合同处理人办理的工单），但不因此获得其他后道模块的团队数据范围。

- 业务组长在具体入职/离职模块（主工单 + 子工单）只看本人发起数据。
- 仪表盘团队视角继续按既有权限展示，侧栏不再提供团队工单聚合列表。
- 后道普通模块列表需显示“发起人”列。
- 子工单详情页需显示工单发起人。

## 6. 我的工单规则（已废除）

- 聚合列表路由 `/my-work/*`、`/my-dispatched`、`/team-dispatched`、`/dispatched-orders`、`/work-order-pool` 全部禁用；管理员、全量权限和动态权限配置也不得重新开放。
- `/my-dispatched/:id` 仅保留为业务模块和消息通知使用的子工单详情地址，不得恢复为聚合列表或侧栏菜单。
- 原“我的待办、我的已办、我发起的、我的退回、团队工单、历史工单”筛选和批量操作口径停止执行；对应工作从具体业务模块完成。

## 7. 表格筛选规则

以下页面必须支持表头字段筛选：
- 我的工单所有子页面
- 团队工单
- 历史工单
- 入职/离职子工单页面
- 入职/离职主工单页面

主工单筛选字段至少包含：
- 工单编号
- 客户代码
- 客户名称
- 员工姓名
- 员工证件号
- 发起人
- 订单类型

子工单筛选字段至少包含：
- 工单编号
- 子工单类型 / 工单类型
- 客户代码
- 客户名称
- 员工姓名
- 员工证件号
- 发起人
- 状态
- 实际操作人 / 配置负责人

## 8. 子工单详情页规则

- 必填字段用红色 `*` 标识。
- 选填字段不显示“选填”。
- 不要在字段旁显示“必填”文字。
- 子工单详情必须显示工单发起人。
- 我的工单、历史工单、团队工单入口进入详情后都应可按权限操作。
- 子工单详情“返回列表”应优先回到进入详情时的来源页面；来源缺失、非法或当前角色不可访问时，才回到该详情类型的默认安全列表。
- 所有子工单详情字段均以当前业务范围、当前模块在管理后台最新启用的“详情页字段配置”为准；活动模板中的字段对所有已获该工单读取权限的用户直接显示，且按模板配置排序，模板外字段隐藏。没有活动模板时才沿用该模块既有字段快照或正式字段白名单。
- 字段权限不得再隐藏活动详情模板选中的字段：原为 `hidden` 或未配置的模板字段在详情中降为只读，`masked` 继续脱敏，原有 `visible`/`readonly` 保持原权限；该规则不授予其他工单的数据访问权，也不扩大编辑权限。劳动合同已接单或已完成工单仍走 `modify_pending` 修改审批，不获得管理员流程豁免。

## 9. 正式上线账号与首次改密规则

- 登录后主布局顶部必须有可见的“修改密码”入口；该入口是账号安全操作，不得通过新增业务菜单项或修改 `routeVisibility`/菜单矩阵实现。
- 默认密码首次登录后必须进入修改密码链路；前端修改密码请求必须向后端 `/auth/change-password` 传 `oldPassword` / `newPassword`，不得只传 `old_password` / `new_password`。
- 登录响应、`/auth/me` 刷新恢复和 mock refresh 必须同步 `mustChangePassword`/`must_change_password` 到 `userStore.mustChangePassword`；改密成功和退出登录后必须清除该标记，避免继续被路由守卫拦截。

## 10. 审批规则

- 未接单：业务员修改 / 撤回 / 作废无需后道审批，只通知后道。
- 已接单：业务员修改 / 撤回 / 作废必须提交后道审批。
- 已接单后业务员修改应进入 `modify_pending`，并保存修改记录。
- 后道审批通过修改后，应用业务员提交的字段修改；审批接口成功后，当前详情和返回的保活列表必须立即显示新状态，不得要求手动刷新页面。
- 已完成：业务员修改 / 撤回 / 作废必须进入对应审批状态，原数据在审批通过前不生效；修改审批通过或拒绝后恢复 `completed` 时保留原办结时间。
- 已完成子工单可由当前办理人、模块主管或管理员填写原因后退回；业务员不能直接执行退回。
- 修改字段若会影响其他已完成兄弟子工单，仍需阻止一次审批跨模块生效，必须分别处理。

## 11. 批量操作规则

- 后道待办需要支持批量接单。
- 我的工单相关子页面需要支持批量操作，不能只能单条处理。
- 入职/离职子工单页默认当前月，也可筛历史月份。
- 批量导入完成、批量改指定字段、批量退回需保持既有业务规则。

## 12. 消息提醒规则

- 消息“已读”功能保留：点击已读后提醒可消失。
- “处理”类提醒不能仅点击处理就消失；需工单办结或以其他方式结束（已完成、已作废、管理员删除等）后消失。

## 13. 显示文案规则

- 入职主工单列表按钮显示“入职批量导入”。
- 离职主工单列表按钮显示“离职批量导入”。
- 主工单页面不显示主工单状态列，只保留子工单进度。
- 子工单进度后缀需与子工单状态一致。
- “实际操作人/配置负责人”显示优先级：实际操作人 > 配置负责人 > 负责人未配置。

## 13.1 入职批量导入字段必填规则

- **合同期限与合同终止日期条件必填**：当“合同期限形式=无固定期限”时，“合同期限”和“合同终止日期”均为非必填；固定期限等其他期限形式下两项继续必填。该规则同样适用于单条入职工单新建、编辑和批量导入。

## 14. 全系统导航状态记忆与列表状态保留

- 菜单点击默认进入该菜单上次停留的合法路径，而不是总是回到初始列表；详情页可以作为菜单最近路径。例如从“我的工单 -> 我发起的”进入 `/my-dispatched/:id`，切到“我的退回”后再点“我发起的”，应回到刚才详情页。
- 最近路径机制应尽量覆盖全系统菜单，不只覆盖“我的工单”。同一菜单下的列表、详情和带查询参数的合法路径应保持归属关系。
- 登录、改密、403、404、新建、导入等临时动作页默认不写入菜单最近路径；如后续新增临时动作页，需要同步加入排除项。
- 最近路径不能绕过权限：点击菜单前必须校验当前角色仍可访问该 lastPath；无权限、不合法、无路由匹配或当前阶段隐藏时，必须回退到该菜单默认 path。
- 入职/离职主工单共用 `/work-orders?orderType=onboarding` / `/work-orders?orderType=resignation` 时，菜单高亮、展开、跳转和最近路径必须按完整 pathname + search 区分，不能互相串扰。
- 列表状态应尽量保留筛选、月份、页码、pageSize、视图模式、表头筛选等状态；状态缓存需按列表/菜单作用域隔离，避免 A 列表状态污染 B 列表。
- 临时动作完成后返回列表时，应优先恢复原列表状态；但如果 URL 明确携带新查询条件，以 URL/用户最新操作为准。
- 该规则调整后至少覆盖 `BasicLayout.test.tsx`、`routeVisibility.test.ts`、`MultiViewTable/index.test.tsx`；涉及子工单详情返回来源时，还需覆盖 `MyDispatched/Detail/index.test.tsx`、各入口列表页测试和 `dispatchedDetailNavigation.test.ts`，并尽量运行 `./回归测试.ps1 -FrontendOnly`。

## 17. 电子签平台路由 / 离职三拆 / 入职 60 字段对齐 / 下拉选项集覆盖 / 三套导出模板

- 入职导入表以《工单管理系统-入职导入模板 (0724修改).xlsx》为权威口径（60 字段）：主表固定为第 1 行填表说明、第 2 行字段名、第 3 行是否必填、第 4 行填写要求、第 5 行填写示例，数据从第 6 行开始；B:AE 表头标黄，AF:AN 使用模板原浅色分区，AO:BI 为外服客户经理填写区。移除毕业院校、专业、毕业时间和邮编，保留学历，新增开户地；`company_address` 表头使用“劳动合同主体注册地”，旧“甲方住所”等名称仅作为历史导入别名兼容。字段顺序由 `import_template_fields` 统一维护，启动种子不得恢复旧 63 字段顺序；下拉必须按字段重新生成正确引用，不复制参考文件中的错位校验或已移除“性别”字段的残留隐藏选项。
- Excel 输入字段与系统字段全集必须分开：`gender`（性别）、`birth_date`（出生日期）、`age`（年龄）是启用的系统标准字段，但不得出现在客户填写的入职导入模板中；`postal_code`（邮编）同样保留为 active 系统字段，但不进入标准入职导入模板。导入预览和正式落库都必须根据中国大陆身份证号自动派生前三项并写入工单数据，详情页按字段权限正常显示，禁止因模板删列而停用或删除系统字段。
- 下拉选项口径：所有「是否」类字段下拉一律为「是 / 否」，**唯一例外**是「是否电子签」(need_esign) 为「1.是 / 2.否」（含其条件必填表达式 need_esign=1.是、esign_platform 依赖 need_esign=1.是）。导出/导入模板对 need_esign 渲染 1.是/2.否、对其余是否字段渲染 是/否。不得再把全部是否字段统一改成 1.是/2.否。
- 条件必填：need_company_contract=是 → contract_subject/need_contract_urge 必填；need_company_payroll=是 → payroll_location 必填；need_onboarding_contact 必填；need_onboarding_contact=是 → is_common_template 必填，`feedback_deadline` 按 0724 模板固定为非必填；template_name 仅在 need_onboarding_contact=是 且 is_common_template=否 时必填（方案A翻转：通用模板=是→非必填，通用模板=否→必填；2026-06-25 覆盖原“通用模板=是时必填”口径）。另：后台“导入模板配置”对 is_common_template/template_name 等条件字段显式设置导入必填覆盖（isRequiredOverride 非 null）时，以后台配置为准并清掉内置条件必填，使导出模板与后台页面显示一致。`contract_template`（劳动合同模板（标准模板/特殊模板））仍出现在业务员入职导入模板中，但在导入下载/校验阶段不作必填（导入阶段清空其条件必填），导入不强制填写；其在单条新增页面仍按 need_company_contract=是 条件必填。
- 现住地址条件必填：`need_onboarding_contact=否` 时 `current_address` 必填；其他情况保持非必填。单条新建、子工单修改/重提、导入预览和正式导入必须执行同一规则。
- 试用期条件必填：`probation_start_date` 非必填；其有值时 `probation_months`、`probation_end_date`、`probation_salary` 必填。导入根据开始日期和月数自动生成的结束日期视为已填写。

- Excel 空白表示保留既有配置；部分更新按字段合并，不清除其他配置。显式 false 必须保留，格式错误、未知字段、非法邮箱、越界账单日及无效 UUID 必须报告失败。
- 历史带入仅读取北仑已提交的有效入职、离职工单（pending/processing/completed），按最近更新时间填充客户级可信字段白名单；草稿、退回、撤回、作废及菜鸟工单排除。已有人工值（含 false）优先，重复带入幂等。

## 45. 2026-09-10 会议门户表单、客户配置与缴纳地规则

- 门户增员按“基本信息 → 合同相关信息 → 社保公积金 → 银行卡与确认”四步填写；合同工资放合同信息，其他工资项目可填文字。试用期选填，合同日期不自动启用试用期；主动填写任一试用期字段时补齐开始日期、月数和工资。
- 门户银行卡提示固定为“如不由外服联系员工收集该信息，则需在本次收集页面填写。”门户初始受理不统一要求银行卡；内部工单不集约收集时的银行卡校验继续生效。
- 特殊城市通过社保公积金备注接收；门户客户可提交尚未维护的实际缴纳地，空缺配置留待内部审核。此为门户受理例外，不改变第 40 节内部新建、修改及通用导入使用正式城市目录的规则。
- 门户公积金比例由客户按缴纳地允许选项选择；切换缴纳地清空旧比例；未知缴纳地不得编造比例。客户通用或历史公积金默认值不能覆盖客户本次选择。
- 发薪周期、发薪日、是否需要工资单在客户规则及 UUID 批量 Excel 维护；实际配置非空入职规则时员工类型必填。已购产品、服务费、保证金为非必填信息或提醒，不生成产品子工单，不从员工历史金额推测。
- 薪资所属月份按客户配置的“当月发当月／当月发上月”给出明确年月，跨年按上月正确计算；薪资提醒仍固定为账单日前 3/2/1 个工作日。
- 同一客户 UUID 下复用既有 Branch 商社，按缴纳地精确匹配商社 UUID 及差异规则；商社必须有效、归属该客户和业务范围。账号仍归属客户，客户无需选择或理解商社编码。禁止按同名客户、相同编码或首个商社猜测匹配。
- 未匹配配置的门户资料创建待内部审核草稿，不自动派单。内部可点击“填充待提交草稿”，仅填充真实门户受理记录对应、尚未提交的 draft 空字段；已有人工值（含 false）、商社选择优先，已提交或已处理工单不改写，补齐写审计且可重复执行。缺配置标记由系统维护，普通修改接口不得清除后绕过提交门禁。
- 离职沿用“社保公积金停保月（几月不产生费用填几月）”口径，内部工单仍保存现有月份值；门户受理记录保留原始 YYYY-MM 以便跨年核对。
- 门户 Excel 校验实际模板表头位置（入职第 2 行、离职第 1 行）及客户 UUID、业务、字段版本；不得增加任意列。批次附件由页面单独上传，随受理保存进入共享邮箱队列，不要求附件分类。

## 46. 2026-09-11 门户审核、自动通知与全过程监控

- 门户增减员保持“受理草稿 → 内部核验 → 按既有规则派单 → 子工单办结 → 门户结果”流程，提交或 Excel 导入不自动派单。管理员或该客户有效配置的业务员/业务组长可认领未提交草稿；业务负责人只读，后道账号不能认领。
- 审核认领必须核对真实受理记录、客户 UUID、业务类型、请求和输入摘要；与提交使用同一数据库锁。已提交、已有子单、其他人已认领的资料不得抢占；认领记录保存原创建人和审核人，普通工单的数据范围不扩大。
- 门户审核资料按现有 main 场景字段权限显示和编辑；普通更新不能变更客户、审核部门、商社或 portal_ 来源标记。布尔客户规则按实际下拉选项显示及提交（如 false 对应 2.否），不把显示转换当作人工修改，不覆盖原有人工值。缺配置、内部必填、附件和派单门禁仍生效。
- 门户结果只返回客户授权业务范围的真实子单状态、办结时间和结果；排除薪酬银行卡导出专用子单，不返回内部处理人标识、内部备注等数据。薪资继续在本系统内部办结，三类办结结果均支持通用邮件模板和结果附件。
- 账号首次开通、停用后重新启用与开通通知在同一事务落库；通知不包含密码、密码哈希或令牌。每月 1 日收集薪资；账单日前 3/2 个工作日通知有效薪资账号，前 1 个工作日通知该客户已配置的有效业务员邮箱。节奏不可调整，没有收件人时明确失败，禁止猜测联系人。
- 发送前重新核验客户/账号有效性、薪资授权、客户规则和目标所属期是否已提交；过期、收权、停用或已提交的催办取消。数据库唯一键防止重复入队，发送任务原子领取并按领取令牌完成，失败可重试；已发送和已取消的自动通知不能手工重复发送。SMTP 接收后异常断线仍可能产生重复投递，不能宣称绝对只投递一次。
- 管理员维护通用模板、签名、发送小时、门户网址及节假日/调休工作日。默认工作日为周一至周五，未配置的法定假期不自动推测；跨月、跨年提醒按账单日前实际工作日倒推。SMTP 允许后配，发送关闭时保留队列，不显示为已送达。
- 全过程监控页面和查询 API 仅管理员可访问。后台受理、办结和回传时间分别来自真实已提交数据、真实完成状态以及成功进度响应加网关响应完成证据；returned 表示“结果已回传”，不表示业务退回。未配置或缺心跳显示监控未连接，失败、超时、缺受理记录分别呈现。
- 每轮网关转发使用独立 attemptId；业务 requestId 继续作为幂等键，接收确认和结果回执必须匹配当前轮次，迟到的旧回执不得进入新请求。监控日志只保存白名单追踪元数据，不保存业务正文、员工资料、附件或密码令牌；ACK、重试、进程恢复不能丢失在途请求证据，重启后无响应证明的请求记为超时。
