# 权限管理功能测试方案（2026-05-13）

## 1. 测试范围与当前结论

本方案仅用于“权限管理功能”的测试准备，按任务要求暂不执行完整测试，待前后端修复完成后再执行。

当前代码阅读结论：

1. 管理后台入口：`/admin/*` 仅 admin 角色可访问。
2. 角色管理页面：`/admin/roles`，文件 `frontend/src/pages/Admin/Roles/index.tsx`。
3. 字段权限页面：`/admin/field-permissions`，文件 `frontend/src/pages/Admin/FieldPermissions/index.tsx`。
4. 用户角色分配入口：`/admin/users`，文件 `frontend/src/pages/Admin/Users/index.tsx`。
5. 后端接口：
   - `GET/POST/PUT/DELETE /api/admin/roles`
   - `GET /api/admin/field-permissions/matrix`
   - `POST /api/admin/field-permissions/batch`
   - `POST /api/admin/field-permissions/copy`
6. 已知待重点复测风险：
   - `allRoles.filter is not a function`：角色页面表单上级角色下拉依赖 `allRoles` 必须是数组，若服务层直接返回分页对象 `{ list, total }` 或异常对象，会触发页面崩溃。
   - 字段权限矩阵前后端契约疑似不一致：前端期望 `{ roles, fields, matrix: MatrixRow[], scenarios }`，后端当前 `getMatrix()` 返回 `{ scenarios, matrix: Record<roleId, Record<scenario, Record<fieldCode, permission>>> }`，且没有返回 roles/fields 列表；真实字段权限管理可能尚未完整联通。
   - 前端字段权限页面当前提示“只读展示，批量编辑接口预留”，需要确认是否属于预期范围。

## 2. 关键功能点

### 2.1 访问控制

- 未登录访问 `/admin/roles`、`/admin/field-permissions` 应跳转登录页。
- 非 admin 用户访问 `/admin/*` 应跳转 403。
- admin 用户可访问管理后台全部权限管理页面。
- 后端 admin 接口必须拒绝非 admin token，不能只依赖前端路由。

### 2.2 角色管理

- 角色列表加载、空列表展示、分页对象兼容。
- 角色字段展示：编码、名称、层级、描述、状态。
- 新建角色：必填校验、编码格式校验、默认启用、保存成功刷新列表。
- 编辑角色：回填当前数据、保存成功刷新列表。
- 上级角色选择：可选择其它角色；编辑时不能选择自己作为上级。
- 删除/禁用角色：仅 admin 可见删除按钮；被用户或字段权限引用的角色应删除失败并提示；无引用角色删除成功。
- 异常保护：接口返回对象、空对象、null、错误码时页面不能白屏，不能再次出现 `allRoles.filter is not a function`。

### 2.3 字段权限矩阵

- 场景下拉加载：至少包含 `main` 及各 `dispatched:*` 场景。
- 矩阵数据加载：行=字段，列=角色，单元格=权限模式。
- 权限标签映射：`visible`、`hidden`、`readonly`、`masked` 均应正确展示；若设计使用 `editable`，需确认并统一前后端枚举。
- 空角色、空字段、空权限记录时，页面应展示空态或默认隐藏，不应白屏。
- 切换场景应重新请求并更新矩阵。
- 后端 `batch`、`copy` 接口如已接入前端，应验证批量保存、复制权限、事务回滚。

### 2.4 用户角色分配联动

- 用户列表能正确展示角色标签。
- 新建/编辑用户时角色下拉来源于角色接口，并只展示可分配角色。
- 保存用户角色后，重新登录或刷新 `/api/auth/me` 后权限生效。
- 用户多角色时，字段权限合并策略应按后端规则生效：`visible > readonly > masked > hidden`。

### 2.5 真实权限配置生效

- 真实组织角色、用户、部门、模块处理人、字段权限种子数据应一致。
- admin 可管理配置；业务负责人只读且不能进入 admin 后台。
- 业务组长具备“查看本组 + 作为业务员操作本人工单”双身份。
- 共享团队负责人可查看并代理处理合同/入离职两条线。
- 合同专员处理合同、续签、待遇申报等合同类模块。
- 入离职联系专员处理入职联系、离职联系、离职证明。
- 数据录入组长可处理数据录入模块并具备组内管理能力。
- 社保模块已下线时，相关角色/字段/派发规则状态应一致，不能出现前端可填但无人处理的数据孤岛。

- roles 为空：`[]`
- fields 为空：`[]`
- matrix 为空：`[]` 或 `{}`

- API 返回旧矩阵结构：`{ scenarios: [], matrix: {} }`
- API 返回前端期望矩阵结构：`{ roles: [], fields: [], matrix: [], scenarios: [] }`
- API 返回错误：401、403、404、409、500
- 网络超时/断网
- token 缺失、token 过期、token 与用户状态不一致
