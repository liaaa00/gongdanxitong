# 用户登录故障排查指南

## 适用场景

遇到「只有管理员账号可以登录，其他账号都无法登录」的问题时，请按以下步骤排查。

---

## 步骤 1：使用内置诊断工具

访问管理后台的登录诊断页面（需要先用 admin 登录）：

> **路径**：管理后台 → 登录诊断（`/admin/login-debug`）

该页面会显示：
- **本地存储诊断**：列出所有用户及其密码状态（有密码/无密码）
- **登录验证结果**：自动验证 9 个种子用户是否可正常登录
- **当前密码明文**：直接显示每个用户在 localStorage 中存储的密码

### 常见诊断结果

| 验证状态 | 含义 | 解决方法 |
|---------|------|---------|
| ✅ 可登录 | 该用户密码正确 | 无需处理 |
| ⛔ 无密码 | localStorage 中缺少该用户的密码记录 | 见步骤 2 |
| ⛔ 密码错误 | 密码与种子默认值不匹配 | 见步骤 2 |
| ⛔ 无用户 | 用户数据丢失 | 见步骤 3 |
| ⛔ 已禁用 | 用户被设置为禁用状态 | 在用户管理页启用 |

---

## 步骤 2：点击「重置所有种子密码」

在登录诊断页面点击 **「重置所有种子密码」** 按钮，所有 9 个种子用户的密码将恢复为默认值。

或者，在用户管理页面（`/admin/users`）找到对应用户，点击 **「重置密码」** 按钮。

---

## 步骤 3：点击「清除所有缓存」

如果重置密码无效，点击登录诊断页面的 **「清除所有缓存」** 按钮。

> ⚠️ 注意：此操作会清空 localStorage 中所有认证相关数据，页面会自动刷新。刷新后种子数据将自动重新初始化。

---

## 步骤 4：手动清除浏览器缓存

如果上述步骤仍无法解决，请在浏览器中手动操作：

1. 打开浏览器开发者工具（F12）
2. 切换到 **Application**（应用程序）标签
3. 在左侧找到 **Local Storage** → 你的网站域名
4. 删除以下 key（如有）：
   - `mock_admin_users_v1`
   - `mock_admin_passwords_v1`
   - `mock_session_user_v1`
   - `token`
   - `refresh_token`
5. 刷新页面（F5）

---

## 步骤 5：使用浏览器控制台诊断

在浏览器控制台（F12 → Console）中运行：

```javascript
// 诊断所有用户密码状态
diagnoseAuth()

// 自动修复缺失的密码
fixAuth()
```

`diagnoseAuth()` 会输出所有用户的密码匹配情况。
`fixAuth()` 会为所有缺少密码的用户自动创建默认密码（admin → admin123，其他 → 123456）。

## 新建用户注意事项

1. 新建用户时必须填写密码（必填项，至少 6 位）
2. 密码会在创建时自动存储到 localStorage
3. 新建的用户在「用户管理」页的「密码」列可以看到「已设置」标签
4. 如果密码列显示「未设置」，说明该用户的密码未成功保存，请删除并重新创建
5. 新建用户后，使用该账号登录前建议刷新页面，确保 localStorage 数据已同步

---

## 如果问题依然存在

1. 确认前端运行在 **Mock 模式**（`VITE_USE_MOCK=true`），Mock 模式下密码存储在 localStorage
2. 如果是真接口模式（`VITE_USE_MOCK=false`），登录验证由后端处理，请检查后端用户表中是否存在对应用户及密码
3. 确认浏览器未禁用 localStorage 或处于隐私模式（无痕浏览可能导致 localStorage 不稳定）
4. 尝试使用不同浏览器或清除浏览器全部缓存后重试
