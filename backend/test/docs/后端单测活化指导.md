# 后端单测活化指导

目的：把 `backend/test/*.spec.ts` 的 `describe.skip` 模板活化成可运行单测时，尽量少改动测试骨架，直接替换 import、mock 和断言。

> 说明：当前仓库里 `dispatch-engine` 与 `field-permission` 已有真实实现；`work-order.service.ts` 在 `backend/src` 中**尚未落地**，因此该模板先按“待补服务”写法给出目标路径与依赖清单，后端补齐服务文件后即可直接套用。

## 1. DispatchEngine / ConditionEvaluator

### 1.1 真实 import 路径
```ts
import { Test } from '@nestjs/testing';
import { getRepositoryToken } from '@nestjs/typeorm';
import { DispatchEngineService } from 'src/modules/dispatch/dispatch-engine.service';
import { ConditionEvaluatorService } from 'src/modules/dispatch/condition-evaluator.service';
import { DispatchRule } from 'src/entities';
import type { Repository } from 'typeorm';
```

### 1.2 最小 mock 集
- `Repository<DispatchRule>`
  - `createQueryBuilder()`
- `ConditionEvaluatorService`
  - `evaluate(ast, fields)`
- QueryBuilder 链式对象
  - `where()` / `andWhere()` / `orderBy()` / `addOrderBy()` / `getMany()`

### 1.3 推荐测试入口
- `DispatchEngineService.evaluate()`：验证命中、去重、`astTrace`。
- `ConditionEvaluatorService.evaluate()`：验证 AST 语义与边界值。

### 1.4 可直接复制的 arrange / act / expect 片段
```ts
const qb = {
  where: jest.fn().mockReturnThis(),
  andWhere: jest.fn().mockReturnThis(),
  orderBy: jest.fn().mockReturnThis(),
  addOrderBy: jest.fn().mockReturnThis(),
  getMany: jest.fn(),
};

const dispatchRuleRepository = {
  createQueryBuilder: jest.fn(() => qb),
} as unknown as Repository<DispatchRule>;

const evaluator = {
  evaluate: jest.fn(),
} as unknown as ConditionEvaluatorService;

const service = new DispatchEngineService(dispatchRuleRepository, evaluator);

qb.getMany.mockResolvedValue([
  {
    id: 'rule-1',
    ruleName: 'data entry',
    priority: 1,
    targetModule: 'data_entry',
    dispatchStrategy: 'pool',
    triggerConditions: null,
    isActive: true,
    createdAt: new Date(),
  },
]);

evaluator.evaluate.mockResolvedValue({
  result: true,
  trace: { node: null, result: true, reason: 'empty ast treated as true' },
});

const result = await service.evaluate({
  orderType: 'onboarding',
  fields: { need_onboarding_contact: '否' },
});

expect(qb.where).toHaveBeenCalledWith('rule.orderType = :orderType', { orderType: 'onboarding' });
expect(result.targetModules).toEqual(['data_entry']);
expect(result.matchedRules).toHaveLength(1);
expect(result.astTrace['rule-1']).toBeDefined();
```

### 1.5 典型断言建议
- 空 AST / 空对象应返回 `result=true`。
- `AND` / `OR` / `NOT` 的短路行为要单独测。
- 同一 `targetModule` 多条命中时，`priority` 最小者保留，其他 hit 标记 `deduped=true`。
- `REGEX` 需要检查超时或熔断（当前实现通过 `safeRegexTest(..., 100)`）。

## 2. FieldPermissionService

### 2.1 真实 import 路径
```ts
import { Test } from '@nestjs/testing';
import { getRepositoryToken } from '@nestjs/typeorm';
import { DataSource, Repository } from 'typeorm';
import { FieldPermissionService } from 'src/modules/admin/field-permissions/field-permission.service';
import { FieldPermissionMode, FieldPermission, FieldConfig, Role } from 'src/entities';
```

### 2.2 最小 mock 集
- `DataSource`
  - `transaction(callback)`
- `Repository<FieldPermission>`
  - `find()` / `findOne()` / `createQueryBuilder()`
- `Repository<FieldConfig>`
  - `find({ where: { isActive: true } })`
- `Repository<Role>`
  - 当前模板未直接调用，但测试模块注入时需要占位。
- `EntityManager`
  - `findOne()` / `save()` / `create()`

### 2.3 推荐测试入口
- `getMatrix()`：验证 scenario 分组与角色矩阵。
- `batchUpsert()`：验证事务内 upsert 行为。
- `copyToRoles()`：验证跨角色复制。
- `filterExtraData()`：验证 hidden/masked/readonly 的过滤与脱敏。

### 2.4 可直接复制的 arrange / act / expect 片段
```ts
const fieldPermissionRepository = {
  find: jest.fn(),
  createQueryBuilder: jest.fn(),
} as unknown as Repository<FieldPermission>;
const fieldConfigRepository = {
  find: jest.fn(),
} as unknown as Repository<FieldConfig>;
const roleRepository = {} as Repository<Role>;

const manager = {
  findOne: jest.fn(),
  save: jest.fn(),
  create: jest.fn((entity, payload) => payload),
};

const dataSource = {
  transaction: jest.fn(async (cb) => cb(manager)),
} as unknown as DataSource;

const service = new FieldPermissionService(
  dataSource,
  fieldPermissionRepository,
  roleRepository,
  fieldConfigRepository,
);

fieldPermissionRepository.find.mockResolvedValue([
  { roleId: 'role-1', scenario: 'main', fieldCode: 'id_card_no', permission: FieldPermissionMode.MASKED },
  { roleId: 'role-1', scenario: 'main', fieldCode: 'mobile', permission: FieldPermissionMode.VISIBLE },
]);

const matrix = await service.getMatrix();
expect(matrix.scenarios).toEqual(['main']);
expect(matrix.matrix['role-1']['main']['id_card_no']).toBe(FieldPermissionMode.MASKED);

fieldConfigRepository.find.mockResolvedValue([
  { fieldCode: 'id_card_no', isActive: true },
  { fieldCode: 'mobile', isActive: true },
]);
fieldPermissionRepository.createQueryBuilder.mockReturnValue({
  where: jest.fn().mockReturnThis(),
  andWhere: jest.fn().mockReturnThis(),
  getMany: jest.fn().mockResolvedValue([
    { fieldCode: 'id_card_no', permission: FieldPermissionMode.MASKED },
    { fieldCode: 'mobile', permission: FieldPermissionMode.VISIBLE },
  ]),
});

const filtered = await service.filterExtraData(
  { id_card_no: '330102199001011234', mobile: '13800138000', remark: 'ok' },
  ['role-1'],
  'main',
);

expect(filtered.id_card_no).toContain('330102');
expect(filtered.mobile).toContain('138');
expect(filtered.remark).toBeUndefined();
```

### 2.5 典型断言建议
- `mergePermissions` 优先级：`visible > readonly > masked > hidden`。
- `hidden` 字段必须从返回结果里彻底移除。
- `masked` 字段不要回传明文。
- `getAvailableExportFields()` 只能返回启用字段且非 hidden。

## 3. WorkOrderService（当前未落地，先按目标服务准备）

### 3.1 现状说明
当前仓库中未发现 `backend/src/modules/work-orders/work-order.service.ts`、`work-order.controller.ts` 或对应 module，因此 `backend/test/work-order.service.spec.ts` 仍处于模板态。若后端后续补齐，建议优先采用下面的目标路径：


### 3.4 先测哪些流程
- `create()`：草稿工单写入 `extraData JSONB`。
- `submit()`：字段校验 → 调度引擎 → 子工单落库 → 幂等性。
- `completeChild()` / `checkMainOrderComplete()`：所有子工单完成后主单完成。
- `supplement()`：补充日志 + 主单回写。
- `return()`：子单退回后主单状态变化。

### 3.5 当前建议
在 `backend/test/work-order.service.spec.ts` 保持 `describe.skip` 直到服务文件落地；否则单测路径会长期漂红。
